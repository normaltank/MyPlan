# 高校师资浏览器采集

## 先读取共同指导

先读根目录 [AGENTS.md](../../../AGENTS.md) 和 [CONSTITUTION.md](../../../CONSTITUTION.md)。业务要求以用户最新确认及这两份当前指导为准；本技能说明现有采集工具的用法，不另设采集范围或永久架构规则。旧案例和架构文档只作为查证线索。

当前工作重点是提高采集准确度、完整度与成功率，并审查代码是否一致、可维护；服务器部署和邮件／飞书通知留待后续。现有路线是 Agent 核实来源与页面结构、真实浏览器访问、可复用代码提取和核验数据。修改这条路线须连同调用方、Schema、测试和真实样本一起验证；文档更新本身不代表实现已经改变。

## 采集与核验口径

- 输入为大学、学院、学院链接，可加师资链接。第四列是优先入口，仍须检查学院其他师资分支；不要把给定链接当作完整范围。自动发现后单独提供四列入口映射是交付目标，实际支持情况以当前实现和验收结果为准。
- 范围是官网明确列为本学院师资的全部人员，包括兼职、外聘等，不限专任。行政事务、新闻、校友、讲座嘉宾等内容不能仅因出现在官网就算作师资。身份或归属不明确时保留来源供复核。
- 主要字段为姓名、职称、邮箱、大学、学院、个人主页、完整简介。尽可能取得个人主页完整正文；官网没有的字段留空，不推测，不把一段摘要当完整简介。没有个人主页不等于没有可用信息，官方名录内可归属到本人的字段仍应保留。
- 同一大学内，证据确认是同一个人后合并学院归属并保留来源；同名、不同 URL 或正文相似都不能单独决定是否同人。不确定的整条记录单独复核，避免把其姓名、邮箱或简介混进已确认结果。
- 允许先交付已确认部分，同时说明未完成学院、分支和待核验问题；这不等于学院采齐。人工确认“无师资”是独立处理结果，自动零人、未找到名录或访问失败都不能代替人工判定。严格空态证明也只适用于已经核实的单个名录分支。

## 现有工单流程

1. **认领与隔离**：现有常驻 worker `python -m server.agent_worker` 从队列取单，`--once` 可用于已安排的排障。IDE／手工路径通过 `/api/queue/pending` 和 `/api/queue/claim/{task_id}` 取单，保留 `school`、`college`、`url`、`roster_urls`、`task_id`、`worker_id`、`lease_token`。按学院隔离任务和证据；派发数量服从当前宿主能力与运行资源，未派发任务继续留队，不伪报已启动。
2. **入口与分支验证**：worker 先执行 `server/recon_discovery.md`，提供第四列时追加 `server/recon_provided_links.md`，再对分支执行 `server/recon_instructions.md`。这些运行提示词由代码加载，根目录指导不会自动注入侦察会话。IDE 路径使用当前宿主实际可用的浏览器工具；不要假定其他环境的工具存在。
3. **选择采集工具**：按实际页面分支读取 [TOOLS.md](TOOLS.md)。普通名录、导航名录、分段文章和图片表格有不同结构契约；不要强制所有页面都使用同一种卡片选择器。URL、选择器、分页与正文范围必须有本轮浏览器证据；完整网页和教师字段由本地代码处理。
4. **对账与补缺**：检查 `branches`、`roster_observations`、`eligibility`、`unresolved`、来源覆盖及字段归属。工具仅对计划内分支完成对账，不能据此证明入口发现没有遗漏。区分来源未发现、访问失败、结构失败、身份冲突和字段错误；只对尚未解决的问题补查。当前 worker 对访问和结构问题使用不同恢复路径，身份争议不能靠重复结构侦察消除。OCR 须与原图核对，图片数不等于教师数；审计和两 Sheet 人数守恒也不等于全院人数完整。
5. **按真实能力同步与交付**：当前同步工具要求 `delivery_ready=true`、有效覆盖证据且 `unresolved=[]`，大学版本还受批次范围和身份冲突门禁约束。按 [TOOLS.md](TOOLS.md) 使用现有接口；不要手改审计、完成状态或复核结果来放行。若该路径尚不能输出业务允许的已确认部分，应保留可确认记录与未解决证据，明确记录部分交付的实现缺口，不能宣称已经支持。当前十列、双 Sheet 是现有文件格式，不是不可修改的业务边界。

三份运行提示词在 `server.agent_recon` 导入时读取。更新后，安排实际试跑时须使用加载新提示词的新进程并记录代码版本，不能假定旧 worker 自动热更新。当前计划缓存摘要包含这三份文件；仍须核对恢复路径和实际运行版本，不能把旧进程产生的计划当作新口径验证结果。

中断恢复、缓存复用和版本下载的实现线索见 [可验证运行流程](../../../docs/architecture/verifiable-harvest-runtime.md)，须结合当前代码核实。恢复时保留原始捕获时间、失败尝试和 Token 审计；不能把重放旧页面当成本轮官网核验。当前版本被重新审计阻断时，不得用旧下载链接冒充已通过当前验收。

## 当前工具契约

- 线上采集使用真实浏览器证据，离线解析和案例重放明确标记其来源和局限。CLI 会另建 Playwright 浏览器上下文，不默认继承宿主浏览器的 Cookie 或页面对象。
- 当前结构侦察计划只允许目标标识、URL、已验证 CSS 和 Schema 定义的结构控制值；不允许加入教师姓名、职称、邮箱、简介、OCR 转写或总结。全文由本地提取和审计流程保存，不用模型摘要替代。不要把底层人工复核证据字段直接塞进模型的 `submit_plan`。
- 选择器与结构证明必须一致；修改任何选择器后重新验证。分页上限和子分支上限仅用于明确限定的范围，不猜测数值来代替页尾和覆盖证明。
- 图片、PDF、共享详情页和无个人主页名单按其实际证据处理。读不到原件、身份不明或归属冲突时保留问题，不能凭空补人或把技术失败改成无师资。
- 旧 HTTP 工单脚本不能作为当前浏览器流程的兜底；离线解析使用 `server.faculty_extractor`，导出使用当前受审计的导出接口。是否调整这些接口由后续代码与样本验证决定。

## 单学院任务交接模板

此模板用于 IDE／主控交接，不替代运行时 `submit_plan` 的严格 Schema：

```text
负责【{school}－{college}】工单 {task_id}，学院入口 {url}，可选师资入口 {roster_urls}。
先读根目录 AGENTS.md、CONSTITUTION.md 和本技能，按当前工具能力执行。
核实本学院全部相关师资入口，包含官网明确的兼职／外聘分支；给定链接仍需补查遗漏。
验证各分支结构、分页和个人页全文范围，按 TOOLS.md 使用工具并保存原始证据。
报告实际完成范围、未解决问题和审计／记录路径；已确认部分与待核验内容分开说明。
自动零人不是人工无师资判定；局部完成不是全院采齐；不编造未实现的导出或复核能力。
```
