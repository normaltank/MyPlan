README 只保留项目简介和快速开始；本文件收录部署、参数、排障与历史验收记录。内容自 2026-09-29 起从 README 原样迁入，未改动含义。

> 本机部署状态（2026-10-01）：内核修复已合入 main 并同步 GitHub，Web 与 worker 已启动；本机地址为 `http://127.0.0.1:18000`，原因和验证见[部署记录](audits/2026-10-01-local-deployment.md)。用户将另选学院测试，旧失败工单不恢复。不要直接执行 `.runtime/restart_after_roster_fix.ps1` 旧草稿或盲目重新入队失败工单。

## 1. 启动与重启（Windows 本机）

```powershell
.runtime/worker-venv/Scripts/python.exe -m server.start_server
```
Windows 本机也可双击 `双击启动局域网服务.bat`。它会检查后台接单心跳，缺少在线消费者时启动常驻 `server.agent_worker`，然后启动网页；已在线的消费者或已监听的网页不会重复启动。两者都已在运行时，窗口会打开网页并提示后等待回车，不会一闪而过。worker 启动自检未通过时，网页顶部会显示"后台接单离线 · 启动自检未通过"和第一条原因。**更新代码后请双击 `重启本地服务.bat`**：它只结束本项目虚拟环境里的接单进程与网页进程（含子进程），再按同样流程重新启动；旧的网页窗口会显示已退出，直接关闭即可。每次启动的过程记录在 `.runtime/launcher.log`。首次启动接单服务时，窗口会要求输入 DeepSeek API Key（输入不回显），并用当前 Windows 账号加密保存在本机 `.runtime/deepseek-api-key.dpapi`；此文件不能复制到其他账号或服务器当作凭据。当前账号后续双击无需重输。worker 日志在 `.runtime/local-worker.out.log` 和 `.runtime/local-worker.err.log`。网页默认端口 8000，本机地址 `http://127.0.0.1:8000`，同事访问见第 2 节。

### 本机端口覆盖

Windows 若将默认 8000 列入 TCP 排除范围，可在 `.runtime/local-services.json` 中设置可用端口，例如 `{"port":18000}`，然后使用正式启动／重启 BAT。该文件不进入 Git，项目默认端口仍取自 `server/config.json`。Web、worker 默认回传地址、手动同步 CLI 和启动脚本共同读取此配置；显式 `--base-url` 优先于默认地址。端口必须是 1 至 65535 的整数，错误配置会在重启停止旧服务之前拒绝执行。端口变了，同事访问地址也跟着变。

## 2. 同事访问：只填姓名（2026-10-09 起）

网页监听 `server/config.json` 里的 `host`，现为 `0.0.0.0`，即本机和局域网都能访问。启动窗口会打印"同事访问地址"，形如 `http://192.168.x.x:18000`，同事在浏览器里打开即可。这个地址只从公司内网常用的私有网段里挑，开着 Clash 等代理的 TUN 模式时也不会给出 198.18.x.x 这类虚拟网卡地址；Windows 上会优先选有默认网关的网卡（Wi-Fi 或网线），WSL、Hyper-V 的虚拟网卡不算。找到多个时会全部列出，发和同事在同一网络的那个。首次启动时 Windows 若弹出"是否允许 Python 访问网络"，只勾选"专用网络"，不要勾"公用网络"。办公电脑的 IP 最好在路由器上固定，否则地址会变。只想本机使用时，把 `host` 改回 `127.0.0.1`。

打开网页时填写姓名即可，没有密码，也没有管理员。同一个名字就是同一个人：工单、复核决定和每日统计都记在这个名字下，浏览器会记住 30 天，点右上角"换个名字"可以重填。所有人都能看到、复核和下载全部工单；每日统计顶部是自己的数，下面按姓名列出当天有工作的人。教师记录数按完成工单统计，复采会再次计入，因此它表示工作量，不表示跨工单去重的人数。以前用账号密码建过的账号，按它的显示名称填写就会沿用原来的工单记录。

这样做的取舍（badr 10-09 确认）：局域网里任何人都能打开网页提交采集，消耗的是本机的 DeepSeek 额度；名字是自己填的，可以冒填；数据在局域网里以明文 HTTP 传输。因此只在公司内网开放，不要把端口映射到互联网。

仍然保留的限制：没填姓名不能使用任何接口；提交、复核等写操作必须带页面发的 CSRF 令牌且来自同一网址；worker 续租、同步和认领工单的接口只接受本机直连。程序把带有 `X-Forwarded-For`、`X-Forwarded-Proto`、`X-Forwarded-Host`、`X-Real-IP` 或 `Forwarded` 头的请求一律当作远程请求，所以以后若在本机前面加反向代理，这些接口仍不会被远程调用。续租接口的 `lease_seconds` 限定在 30 到 900 秒之间。

## 3. 人工复核：图片文字、邮箱、生僻姓名与来源身份（2026-09-30）

同名有多个个人主页时，在同一复核页选择“不同教师”“同一教师”“按各条选择分组”或“证据不足”。合并须明确主来源，邮箱、职称与主页取主来源，各来源的完整简介都保留；原始观察另存本地。全部人工问题解决后才可重新入队，证据不足不会放行。决定绑定原记录与页面摘要，页面变化后失效；入库和大学版本下载也检查本地决定证据。该入口解决学院内歧义，跨学院新增歧义仍阻断。

工单因图片简介的低置信 OCR 行、邮箱冲突或生僻姓氏的人名被挡住时，工单进度会显示“人工复核”。任何人都可对照原图保存决定。完成该工单的全部图片复核后，点击“重新采集此工单”会使原工单重新入队，保留提交人和原始证据，重新执行确定性审计。原图或 OCR 已变化时，旧决定不会直接套用。旧的 `scratch` 验收材料没有提交人，可从右上角姓名菜单里的“查看历史复核材料”进入；`8765` 是先前的本机独立页面，不再作为新员工工单入口。图片复核只解决其对应的证据问题，其他分支、身份或覆盖审计未通过时仍会阻断交付。

生僻姓氏的人名也在同一复核页确认。常用姓氏表（`Opus/iso_mining.py`）之外、完整姓氏表（`Opus/rare_surnames.txt`，748 个）之内的姓，出现在名录的人名位置时，既不自动收进名单，也不丢弃；页面列出名字、名录页链接和卡片原文，由人选择“是教师，按此姓名采集”（可改正姓名）或“不是教师姓名”。很多生僻姓也是常用字（宿、学、天），所以这一步不能省。有链接、且同组已有至少 3 位可信同事的卡片名录，仍按结构证据直接采信，与以前相同。决定只对完全相同的名录页、个人页、名字和卡片原文生效。只因生僻姓待复核而失败的工单，不再触发侦察补缺。选“不是教师姓名”后，这张卡片仍要有解释，工单会以卡片数不符继续阻断。

分段平铺名录（一篇文章里依次平铺多位教师，或姓名只写在简历图里）使用同一复核页：只在图片中的姓名由本地 OCR 读取，能与该教师自己的文字邮箱全拼核对上时自动采信，核对不上时页面会出现标注“姓名行”的卡片，对照原图改正后保存即可。

网页右侧默认显示本浏览器的当前请求；没有活动请求时显示“待提交”。已结束的旧批次可从“历史工单”主动查看，不会自动占据新任务进度。顶部“后台自动接单在线”取自常驻 worker 的实时心跳；显示离线时提交会入队等待，可重新双击上述 BAT 启动消费者。提交单院或批量任务都必须填写有效的学院官网入口 URL，缺少入口的批量请求整批不会入队。

## 4. 常驻 worker（服务部署或排障）

```powershell
$env:DEEPSEEK_API_KEY = "<你的 Key>"
python -m server.agent_worker
```
worker 常驻轮询 `server/tasks.db`；使用锁定依赖中的 Harness 可执行程序与项目独立 `.runtime/dsh-home`，自动插入项目的 Python Playwright MCP 插件。先安装本环境的 Chromium。`DSH_BIN`、`DSH_HOME` 仅用于明确的自定义部署，不再自动拾取 PATH 上其它版本的 dsh 或用户全局 profile。
它不需要任何反向 Webhook，因此不受 IDE 宿主平台的唤醒限制。
按最新调度要求，worker 对全部待采集学院并行启动独立 Harness 会话，不设置项目级并发上限。每个工单的中间文件隔离在 `server/outputs/tasks/<task_id>/`，同一大学的最终 Excel 写入按序执行。服务器会话只负责结构侦察，确定性采集与交付由 worker 执行；这与 IDE 原生 Subagent 的完整履约职责不同。

侦察由代码分阶段执行：先读取 `server/recon_discovery.md` 核实全部名录 URL，再为每个分支用新的短上下文执行 `server/recon_instructions.md`。阶段只提供对应的真实浏览器工具；每个 URL、卡片选择器与实际下一页都须有本轮浏览器证据。确定性代码合并通过门禁的分支计划，再执行采集。无效计划或未解决审计最多返回侦察补缺两轮（`--max-recon-repairs`），全程保留原工单租约。

侦察默认不按固定请求数或 Token 数截断正常学院。入口发现只提交实际承载名录的页面，避免把菜单页和个人详情页重复当成名录分支；分支验证失败后保留同一工单内已核实的其他分支，只补有问题的分支。补缺反馈只传给对应阶段；若连续两轮仍是同一问题且没有新增已核实分支，停止无进展的重试。运维如需额外费用保险，可同时设置 worker 参数 `--max-recon-calls` 与 `--max-recon-tokens`；两者默认均为 `0`（关闭）。启用后按学院累计计数，缓存输入也计入 Token，达到阈值时失败并保留用量审计。Token 在每次请求完成后检查，因此不是严格费用上限。

**总时限与补缺**：单个学院工单最长 45 分钟（`--max-task-seconds`），单次侦察最长 900 秒（`--recon-timeout`），审计失败后最多补缺两轮。每轮补缺开始前，worker 会为之后的确定性采集预留 600 秒（`--harvest-reserve-seconds`）：剩余时间不够一轮侦察（至少 180 秒）加采集时，不再开始新一轮补缺，工单以 `repair_skipped_task_deadline` 结束，而不是在侦察中途被总时限腰斩；够用但不足 900 秒时，这一轮侦察按剩余时间缩短。

空闲时 worker 查询队列的间隔从 0.2 秒逐步放宽到 2 秒，有新工单后恢复；没有可领工单时不占数据库写锁。

## 5. 资源与用量保护

以下各项 2026-09-29 起默认开启，均可关闭。全部学院仍同时开工，以下几项只限制共享资源：
- 按站点限流：同一大学站点（如 `cs.x.edu.cn` 与 `law.x.edu.cn` 同属 `x.edu.cn`）上，本 worker 所有学院同时打开的详情页合计不超过 8 个。环境变量 `HARVEST_PER_SITE_CONCURRENCY` 可调，设为 `0` 关闭。单院 `profile_concurrency` 仍然有效。
- 官网限流冻结（2026-10-09 起）：平时不限速。某大学站点回限流/封 IP 提示页、HTTP 429 或带 Retry-After 的 503 时，worker、各侦察会话和 IDE 批量工具对这个大学的请求一起暂停到提示的冻结时长结束（默认 10 分钟，限 1 到 60 分钟），再继续原有重试；此后该大学的页面打开和点击每秒最多一个，图片、PDF 原件不限。记录在 `server/outputs/site-clock.sqlite3`（`HARVEST_SITE_CLOCK_DB` 可改），删掉该文件即忘掉。`HARVEST_PER_SITE_INTERVAL_SECONDS` 可另给所有站点按主机名设节拍（默认 0，不设）。
- 内存保护：已有学院在跑、且可用物理内存低于 1024MB 时，worker 暂缓领取新工单，内存恢复后继续；第一个学院不受影响。参数 `--min-free-memory-mb`，`0` 关闭。
- 侦察用量告警：单学院按实际用量分项核算的费用超过约 1 美元，时，只告警、不中断；默认 Token 与请求次数告警均关闭，按需显式开启。告警写入 worker 日志和任务目录的 `recon-usage-alert.json`，并随工单统计保存为 `recon_usage_alerts`。参数 `--recon-alert-cost-usd`、`--recon-alert-tokens`、`--recon-alert-calls`，`0` 关闭。需要硬性熔断时，仍使用上面的 `--max-recon-calls` 与 `--max-recon-tokens`。
- 批量提交上限：单次最多 30 个学院（`server/config.json` 的 `max_batch_colleges`），按学院计数。同一学院的多行（每行一条师资链接）合并为一张工单；同一学院的学院主页前后不一致时整批拒绝。
- 单会话请求上限：2026-09-30 起默认关闭（0），复杂正常网站不因固定请求次数失败。参数 `--max-discovery-calls`、`--max-branch-calls` 可显式开启；开启后达到设置上限会停止该学院并保留审计，状态为 `recon_phase_limit`，但不能由此认定网站结构异常。
- 侦察超时会立即结束对应的 Harness 会话，已发生的用量照常记入 `recon-attempts.json`；以前超时后会话仍在后台继续消耗，且用量记为未知。
- 侦察截图只发送当前视口或指定元素的 JPEG（高不超过 2000px），不再发送整页 PNG；同一页面的重复 HTML 快照只保存一份。

## 6. 启动自检与 Excel 文本安全

常驻 worker 领取工单前，会检查算法层、pypinyin、OCR、PyMuPDF、Harness 运行时、`DEEPSEEK_API_KEY` 和 Playwright Chromium 是否齐全。任一缺失时，worker 在 `.runtime/local-worker.err.log` 写明原因并退出（退出码 2），不会带着降级的依赖继续采集；双击启动脚本会等待自检结果并提示。排障时可加 `--skip-self-check` 跳过。Excel 导出时，抓取到的文本一律按文本写入（以 `=` 开头的内容不会变成公式），xlsx 无法保存的控制字符会被去掉，不再导致整份大学表导出失败。

## 7. 侦察浏览器工具与运行时

`server/recon_browser_mcp.py` 提供真实 Playwright 的精简 MCP 工具，文本按范围返回且单次最多 8000 UTF-8 字节；导航单次最多读取 64 个链接，超过返回预算仍明确给出未读范围。完整 HTML/JSON/截图保存到 `server/outputs/recon-evidence/<phase_session_id>/`。此预算只作用于侦察上下文，教师完整简介与 Excel 不受影响。运行时叠加 `server/recon_runtime.cordis.yml`，关闭无关技能目录、工程文件工具与通用指令注入，并保存每阶段及补缺轮次的真实 Token 元数据。实测结果见 `docs/audits/2026-09-26-harness-context-audit.md`；本次异常用量与修订见 `docs/audits/2026-09-29-nxist-recon-cost.md`。

运行补丁用 `insert` 安装 `dsh-mcp-client`，默认独立 ID 为 `faculty-recon-browser`，无需事先手工配置浏览器插件。阶段与证据会话通过启动参数显式传递。每次模型运行前先检查实际合成配置：浏览器缺失/重复、无关工具或通用指令注入仍启用、补丁未生效时直接失败，不花 Token 试错。自定义 profile 也须通过此检查。先在该环境运行 `python -m playwright install chromium`。编辑侦察 MD 或 Python 后需重启常驻 worker。

发现阶段的 `browser_navigate` 同时返回页面摘要，本会话已返回过的链接和重复的菜单、页脚文字不再重发；`browser_navigation` 可用 `query` 按关键词筛链接；`browser_survey` 一次查看最多 8 个候选页。个人页正文验证未通过时返回 `reason`（如 `hidden_content`、`network_not_idle`）和阻断请求的类型。

正文图片缺少对应 DOM 文字时，侦察可按实际 img 选择器调用 `browser_read_image`：读取当前浏览器加载成功的原图，复用本地 OCR，保存原件及完整文字，按 `nextOffset` 返回文字行和置信度。其结果只作为页面内容观察，不证明教师来源合格，也不替代选择器、分页或交付审计；模型计划仍只包含结构字段。普通 DOM 文字不触发 OCR。

## 8. 固定运行环境

常驻进程使用固定环境，不能从会随启动器退出而清理的临时环境启动后台子进程。本机已使用 `.runtime/worker-venv`，依赖来自 `requirements.lock`：
```powershell
uv venv .runtime/worker-venv --python 3.12
uv pip sync --python .runtime/worker-venv/Scripts/python.exe requirements.lock
.runtime/worker-venv/Scripts/python.exe -m playwright install chromium
.runtime/worker-venv/Scripts/python.exe -m server.agent_worker
```
启动前在进程环境设置 `DEEPSEEK_API_KEY`；不要写入项目文件。

| 命令 | 用途 |
| :--- | :--- |
| `python -m server.agent_worker` | **常驻**（生产形态） |
| `python -m server.agent_worker --once` | 只处理一个工单后退出（**排障用，勿用于生产**） |

> ⚠️ **用 `--once` 跑生产会导致"提单后一直没人接单"**——它处理一个工单就退出。
> 生产环境应由 systemd 守护（Phase 4，尚未交付）。

## 9. 恢复、续采与严格空名录

2026-09-27 新流程已增加覆盖账本、工单页面断点、经本轮浏览器核验的结构方案复用、局部分支补缺及大学交付版本。方案现永久保存于 `server/outputs/plan-cache/plans.sqlite3`，保留历史版本，每次复用仍须本轮浏览器验证。运行条件与文件含义见 [可验证运行流程](architecture/verifiable-harvest-runtime.md)，实测范围见 [实现审计](audits/2026-09-27-verifiable-harvest.md)。

普通 URL 分页中断后可重新验证最后成功页，再续采后续页；同 URL AJAX、变化或损坏的前沿会从分支入口重走。普通单页名录只有明确可见的空态提示、独占容器及本轮独立浏览器证据，才允许确认为空；空白页面、隐藏内容、未加载图片或仍在请求的页面继续阻断。全学院零人结果进入复核，不自动导出，也不重复调用模型补结构。侦察协议更新后，旧结构方案永久保留，但必须符合当前契约才能复用。

## 2026-09-30 运行报告与提速配置

失败动作由 `server/recovery_policy.py` 统一分类：访问问题先本地补缺，已知结构问题才进入模型补缺，人工复核保留证据，未知错误停止。正文入场动画有界等待约 2 秒，仍须连续两次正文及可见性稳定；持续动画或隐藏正文不放行。

名录分支默认并行运行，运行补丁和证据目录分别独立。设置 `FACULTY_RECON_PARALLEL=0` 可回到串行排障；`FACULTY_RECON_TEMPLATE_REUSE=0` 关闭模板复用。结构指纹相同只提供复用候选，目标名录仍重新用真实 Playwright 核验选择器、实际下一页与个人正文；失败回退独立侦察，不跳过页面。交互、分段、空页和无个人详情页的名录不作模板捷径。官网详情页限流及低内存保护不变。

`submit_plan` 在工具调用时校验严格 Schema、当前目标和本轮浏览器证据；Schema 错误只返回受控状态码与字段路径，不能回显不合法的教师字段。证据错误另给分支 URL、选择器、没通过的条件 `failed_condition`、最接近的观察 `closest` 与还缺的证据 `need`。全部是只由页面决定的失败（`page_only`）时结束会话（`recon_page_unverifiable`，按 access 分流）；同一计划无新浏览器证据时重交不重判，第二次结束会话（`recon_gate_stalled`）。超时或预算停止的侦察会在审计和失败信息中记下每个会话最后一次被打回的条件。默认服务器配置必须有成功的提交收据；无需在最终文本重复计划。

每个任务目录的 `runtime-report.json` 汇总全部侦察尝试（包括格式拒绝）、缓存/模板复用、访问重试、阶段耗时、人工问题和费用；最后一次采集 audit 及工单统计也带 `runtime_report`。字段阶段耗时保留在 `stage_seconds`。新报告不会改变快照原捕获时间，不可把恢复或本地页面回放当成本轮实网覆盖。

费用使用 SDK 实际返回的非缓存输入、缓存输入和输出分别计价，价格快照日期为 2026-09-30，来源为 [DeepSeek 官方价格](https://api-docs.deepseek.com/quick_start/pricing/)。按用量通知收到的 UTC 时段核算峰谷价，字段 `estimated_usd` 是估算、并非账单；跨时段请求或后续调价可能产生差异。未知模型/供应商或旧报告缺少价格记录时保留 `unknown_calls`，不会记为零。可用 `FACULTY_RECON_PRICE_USD_PER_MILLION` 设置 JSON 对象 `uncached_input`、`cached_input`、`output` 三项价格（美元/百万 Token，固定覆盖峰谷价），用于自定义供应商或价格更新。费用告警只报告不停止；硬熔断仍由显式 `--max-recon-calls`、`--max-recon-tokens` 控制。

空名录新增保守放行条件：仅原生禁用、没有子元素和事件属性的分页按钮及其空布局包装可忽略。aria-disabled、空链接或点击无变化均不能单独证明禁用。明确空态、零卡片、无隐藏正文/媒体、网络与 DOM 稳定等原门禁保留；整学院零人仍需人工处理。


### 数量门槛核验（2026-09-30）

默认关闭总请求/Token 与分阶段请求硬上限，费用告警只报告不停止。`--max-discovery-calls`、`--max-branch-calls` 仅供明确需要熔断的操作员开启，默认 0。未明确给出 `max_pages` / `max_children` 时不再默认截断于 20 页/30 个子名录；计划显式给出正数时仍执行该范围，最大 100 的格式上限已移除。侦察不得猜测固定数量。实际重复的页面 URL 与正文/控件前沿会报 `pagination_cycle`，访问失败、分页不变或缺少终止证明同样阻断；不会把未采完宣告为成功。

学院数量没有项目级并发上限。详情页并发与官网按站点限流只是等待并继续；低内存时暂缓接新单，已接学院继续；单次批量提交条数限制保留，不代表教师人数限制。单任务 45 分钟、侦察默认 900 秒及导航等待仍是可调整的时间保护，极慢网站可能超时，证据和断点会保留，日志明确说明；不能承诺任何正常网站永远不受时间保护影响。


## 2026-09-30 批量输入、Token 与准确性核对

**批量输入格式**：每行 `大学 学院 学院主页 [师资链接]`，可直接从表格粘贴（制表符分隔时名称可含空格）。第四列可选：

- 同一学院的多条师资链接各占一行，合并为一张工单（`server/intake.py`），链接存于工单的 `roster_urls`。
- 只有三列的学院照旧由侦察在全站发现名录入口。
- 缺少 `http://` 的网址自动补全，首行表头自动跳过；列数不对、网址无效、同一学院主页不一致会逐行报错，整批不入队。
- 师资链接不在学院主页站点上、不在学院主页目录下，或某学院主页与同校多数学院不在同一域名时，接口返回 409 与提示清单，网页显示后需再次点击提交确认。

**给定师资链接的侦察**：链接只是线索。入口发现阶段改为核对这些链接（`server/recon_provided_links.md`），用一次批量打开判断每个链接是否在职专任教师名录；队伍概况、行政与教辅名单、曾执教名单、失效或跨校链接不提交，目录页换成子名单页；都不是名录时才从学院主页核实一次。之后的分支核实、证据门禁、采集与交付不变。这类工单不使用、也不写入按学院主页缓存的计划。人数核对会同时读取全部给定链接，并在结果里列出“采用 / 未采用”的链接及页面标题。

**推理强度**：`DSH_EFFORT` 为默认值（off / low / high / max）；`DSH_EFFORT_DISCOVERY`、`DSH_EFFORT_BRANCH` 可分别覆盖入口发现与分支核实阶段。阶段报告记录实际使用的强度。

**个人页正文核实**：`browser_verify_profile` 可一次传入最多 3 个样例链接；不带选择器时返回候选正文容器与各样例共同通过的选择器；失败时附隐藏元素位置与已通过静态检查的替代容器；网络未静或页面仍在变化时工具内自动再看一次。

**补缺范围**：审计问题都能落到已采用分支时，补缺沿用上一轮入口发现，只重新侦察出问题的分支；出问题的分支不再套用同模板兄弟分支的选择器；补缺后计划与上一轮完全相同则不再重复采集。已核实卡片上认不出的名字（外籍译名等）进入“姓名待确认”人工复核，不再交给模型补缺。

**人数与字段核对**（不拦交付，只提示）：采集结束后 worker 做两类核对，写入审计的 `field_check`、`cross_check`，任务目录另有 `cross-check.json` 明细，网页结果行显示摘要。

- 字段核对：姓名、邮箱是否出现在来源页，邮箱是否多人共用，职称是否在规范词表内，简介是否写的是别人。
- 人数核对：
  - 不用模型的导航普查：打开学院站点菜单页（上限 60 页），用确定性名录读取找出列有人名的页面，列出未入库的姓名与来源页标题。
  - 翻页器“共 N 条”与实采卡片数对照。
  - 学院介绍里的“专任教师 N 人”与入库人数对照。

普查会遇到行政、退休、学生名单，简介人数也可能过时，所以差额是待人确认的问题，不是结论。设置 `HARVEST_CROSS_CHECK=0` 关闭普查（字段核对仍做）；普查最多约 240 秒，受任务截止时间约束。

**邮箱归属（合并后规则）**：名录卡片与个人页以本人范围内明确的联系字段、表格标签或 mailto 为正证据，昵称及数字邮箱不必符合姓名拼音。同级个人页共有的模板邮箱继续过滤；多个标注地址、多卡同标及存在地址但归属不足均保留未解决项，不按页面顺序猜选。图片邮箱沿用原图证据与人工复核流程。

**人工抽检**：`python -m server.spot_check <学院 audit.json> [--sample 30] [--seed N]` 在审计旁生成 `spot-check.html`（随机抽样，有邮箱与无邮箱各半，附原页片段）和 `spot-check-oracle.json`（复核结论模板，字段与 `server/harvest_benchmark.py` 一致）。抽查 n 条全部正确时，错误率在 95% 把握下约不超过 3/n。积累 10–20 个不同类型学院的完整复核即可作为冻结的准确率基准。

**案例库离线回放**：`python -m server.case_replay <案例目录> [--case 名称 ...] [--report 表.md] [--chromium 路径]` 用当前代码重跑保存过的实网案例（每个案例目录含 `plan.json`、`result.json` 和采集时的 `out/`），浏览器的所有请求只由保存的页面和原件应答，没保存的页面和数据请求答 404 并计入 `missing` 列，没保存的脚本、样式、图片答空内容（快照本身就是脚本执行后的页面），不联网、不调模型，OCR 走本地并复用案例里的缓存。输出每个学院“保存时 vs 回放”的就绪、人数和未解决项，首行是两边的就绪学院数，用来看一次代码改动是否让可交付学院变多。同一学院有多次采集时取 `captured_at` 最新的一次。限制：原采集没打开过的页面不在案例里，会计入 `missing` 列，这类学院的回放结果不能当真；子资源在官网是否失效（如访问计数接口 404）回放看不出来。案例库在项目共享目录 `case-library/evidence/`。输出默认写到系统临时目录，不碰 `server/outputs` 的生产 OCR 缓存。
