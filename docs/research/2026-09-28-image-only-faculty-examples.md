# 高校官网图片承载导师简介样本

核查日期：2026-09-28。范围限于高校官网公开页面及其原始附件。这里的“图片承载”指个人简介的文字本身位于位图中；仅有头像、照片而正文仍是 HTML 或 PDF 文字层的页面不算。

## 结论

已核实两所不同高校、两种可重复观察的形态：湖南科技大学信息与电气工程学院把导师简介作为网页中的连续 JPG 发布；西北民族大学舞蹈学院把导师简介放在逐页扫描的 PDF 中。西北民族大学样本在已成功下载的浏览器会话中证实为六页无文字层的图像 PDF；新建 Chromium 会话遇到附件验证码，不能假定服务器能直接下载。首尾页渲染检查确认图像内是连续的导师介绍正文，而非只有头像。[湖南科技大学 2021 年官网页](https://xinxi.hnust.edu.cn/tzgg/02305dcc2ae14b02a54b8c1cf1d51b04.htm)；[西北民族大学 2026 年官网页](https://www.xbmu.edu.cn/wdxy/info/1331/16241.htm)。

- 本轮下载文件的 SHA-256：`f390a44b4d95eea793bffa920dad8c33377674c3e5d7cc73bf910e635e481b18`。该指纹用于区分以后可能替换的附件版本。
- 检查的是 PDF 对象与渲染结果，不是搜索引擎 OCR 摘要。六页均没有可提取文字，且全页图像覆盖正文；因此把它归入扫描 PDF 是直接证据支持的判断。

## 对采集方案的直接含义

这两个样本需要分开处理：HTML 中的原始 JPG 应从浏览器已核实的图片 URL 获取并逐图核验加载；扫描 PDF 应逐页渲染，再做本地 OCR。两者都要保留原图、来源 URL、页或图序号及 OCR 原文，并在正文未读清或页数未核齐时进入复核。以上是由页面形态推导的实现建议，尚非项目代码的实测结果。

## 对当前实现的检查与决策

当前 `server/browser_poster_tool.py` 面向图片名录：它截取整个网页后做本地 OCR，并把结果交给 Agent 核实。这个流程不能直接处理个人简介：湖南科技大学页面的悬浮导航曾遮住元素截图中的文字，而扫描 PDF 根本不是网页截图。`server/faculty_extractor.py` 从 HTML 正文取简介；`server/browser_batch_tool.py` 只会在两个非空文本版本不一致时报告正文差异。若个人页成功打开但正文都在图片中，空简介可能进入交付，因此需要先补交付拦截，再接 OCR。

按真实页面形态决定以下顺序：

1. 在已核实的个人简介正文容器内，对比可提取正文与图片、文档链接；对 PDF 先检查每页文字层和图像覆盖。仅把这些信号作为“需要检查图片内容”的触发条件，不能凭一张头像、大尺寸图片或固定字数阈值认定图片简历。
2. 对网页内图片保留并读取浏览器实际加载的原始图片资源，逐张记录加载状态、来源与页面顺序；对扫描 PDF 保留原件并逐页渲染。避免用整页截图作为正文原件。
3. 本地 OCR 只转写原文，按图片或页的顺序组合，不用模型概括或补写教师字段；同时保存原件、OCR 原文、页数、置信与无法识别位置，供人工复核。
4. 在图片未加载、PDF 页数不全、OCR 缺页或正文归属不明时，形成未解决项并阻止大学版交付。导师名单中的人员仍须经过现有的专任教师资格判定，不能因为有导师简介便自动计入。

这组样本用于湖南科技大学 JPG 页、西北民族大学扫描 PDF、普通 HTML 个人页及“只有头像”的反例验收；通用实现位于 `server/image_biography.py`，没有按学校域名写专用脚本。此处仍保留实施前的决策依据，实际试跑结果见下文。

实施试跑补充：湖南科技大学网页正文含 45 张图片。真实浏览器读取前 3 张原图，本地 OCR 分别识别 56、42、38 行；第三张全文出现两个名单姓名，开头姓名行只有一个。这证实归属依据应放在图片开头。随后以浏览器批量模块只读试跑该 45 图页：候选人 45 名，保存图片原件与 OCR 证据 43 份；当次两个资源访问失败、一个 OCR 置信度不足，导致覆盖核对未通过且不生成正式 Excel。两个失败资源后续单独重试取回，但尚未重新核对整页。西北民族大学附件在新建 Chromium 会话中出现验证码；返回值虽为 HTTP 200，却是 HTML。下载器必须核对 PDF 文件签名，不能以 HTTP 200 推断取得原件。

### 后续整页复跑与跨站排除证据

2026-09-28 的同目录真实浏览器复跑已取得 45/45 张官网原图及 45/45 份本地 OCR。两张图片各有一行低置信文字，未由人确认；复核入口是只监听本机的 `server/image_bio_review.py`。再次运行同一目录时，45/45 份 OCR 都通过原件哈希校验后复用，整轮 19.528 秒。其审计仍为 `needs_agent_review`，正式交付被阻止。上段的 43 份是首次试跑历史结果，不代表当前原件缺失。

### 人工复核后的图片页结果

用户在本地页面确认 2 条低置信 OCR 行。第一次复跑后 45 张原图均可归属，名录数量异常被清除；另发现同一份图片简介内有 2 个符合个人邮箱规则的地址，系统因此继续挡住交付。新增的本地邮箱选择页面呈现两个原图局部，由用户选择交付表中的一个邮箱，完整简介仍保留两个地址所在的原文。最后一次真实浏览器复跑得到 45/45 图片与 OCR 证据、`unresolved=0`、29/16 双 Sheet 守恒；85 项相关测试通过。此 Excel 仅存于 `scratch`，因为 2021 年导师介绍不等于当前专任教师名录，不能作为正式大学交付。
