# 项目工作项入口

技能要求获取 spec 或 ticket 时，先定位用户当前任务及其引用的工单、PR 或已有问题记录；共同业务契约见 [CONTEXT.md](../../CONTEXT.md)，角色按 [AGENTS.md](../../AGENTS.md) 确定。

- 采集维护：以当前采集报错、工单、脚本优化要求和相关 PR 为工作项，保存原始证据、共性修复与回归结果。
- 全链路专项审查：由承担该任务的 agent 读取并维护 [五项计划](../improvement-plan.md)。该计划不作为采集维护任务的默认 spec 或前置步骤。

## 使用规则

- 在当前任务所属的工单、PR 或已有问题条目下记录下一步、证据链接及阻塞条件，不为同一事项再建平行清单。
- GitHub PR 保存具体改动、审查与对应 CI；合并和检查状态直接查询 GitHub，完成后在工作项附证据链接。
- 需要跨 agent 留存的复现步骤、设计或实验结论放入对应的已跟踪项目文档，且由工作项链接。只有内容需要独立阅读时才新增文件。
- 本地 `.scratch/<effort>/` 可以保存临时推演或技能中间产物，但文件存在不等于已共享。交接前核对 `git ls-files` 与实际提交；工作项不得只指向未提交的本机材料。
- 已有外部 issue 或 PR 按其真实链接继续，不因为技能默认使用本地 Markdown 就复制一份。

完成条件是结论与验证证据到位，不是创建了 `Status:` 行或打勾。与权限相关的执行边界见 AGENTS，技能不能另增授权。
