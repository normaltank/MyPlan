# 职称分组姓名网格

结构代码：`pdf_rank_grouped_name_grid`。这是多人 PDF 名录的子形态，观察状态不证明全院完整交付。

原件具有有效文字层和原生格线，每个人员格闭合，职称组标题横跨表宽，没有“姓名”表头。`server/pdf_roster.py` 在现有有表头解析之后、简介分段之前尝试此形态；计划仍声明浏览器核实的 PDF 名录卡片，不增加教师数据字段。

解析按原生单元格位置归属文字，一格一人，格内折行不另起一人。所有组均读取，组标题和格坐标留作来源证据；单一具体职称可供既有职称优先级使用，混合职称只作为组证据，个人保留默认“教师”。简介、邮箱和主页缺失时不编造。人员资格仍由原有来源与资格门禁判定。

无“姓名”表头的生僻/未知单项姓名沿用姓名复核，决定绑定原件 SHA、页码和格坐标。明确分隔的多项、折行后多块文字均有成员歧义，不提供能用一个姓名解除的复核项；仅既有名单规则核准的两/三字逐字空白可合并，四字以上仍阻断。未知第二块也不能自动拼接成姓名，须补结构读取能力。格内或表内相交的小图片、未归属文字、重复姓名、未知组标题或未识别页面不能证明读全，保持未解决。扫描网格、无格线排版、每格多个人、非职称跨行标题尚不支持，不以猜测或姓名黑名单补齐。

观察登记由 `server.site_type_registry.record_audit_shapes` 从保存审计读取，只接受 `kind=pdf_roster`、`layout=rank_grid` 且原件 SHA 同时与附件证据、结构观察相符的项。该形态的导入特征只包含页数、文字/OCR 页数、检测/读取人数与分组数；登记另保存目标、URL、原件路径／摘要和状态。它不是完整类型能力库，不存姓名、职称、邮箱或简介作为特征，也不批准模板／方案。

样本依据：江西理工大学土木与测绘工程学院浏览器取得的 PDF，SHA `60dae466ccf3cdc53f0cb18e9292188be9d4684c209d7627481d2c0c0e332a55`。1 页、4 组、68 个文字人员格，当前读取 67，保留 1 项姓名复核。已在隔离类型库登记 `observed`；未把旧失败工单改成成功。合成测试覆盖单一/混合职称、未知姓名、格内多名、折行歧义、小图片格；旧 PDF 表头续表和简介分段测试保留。

本次样本与 [已合并 PR #12](https://github.com/normaltank/MyPlan/pull/12) 的显式“姓名”列表不同。继续按实际代码读取全部人员组，不恢复该 PR 早期描述中的人员组过滤。相关问题与验收边界见 [修复记录](../implementation/2026-10-10-three-college-structure-fixes.md)。
