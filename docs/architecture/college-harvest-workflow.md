# 学院采集：Agent 计划与浏览器深模块

**状态：通用编排接口已落地；具体院校只作为验收夹具。** [ADR 0005](../adr/0005-plan-driven-browser-harvest.md) 已确定采用计划驱动的通用模块，而非网站类型脚本库。本文件定义模块接口和后续迁移方向。

## 运行环

```text
Agent 浏览器侦察 → 学院采集计划 → 浏览器采集与页面资格判定
       ↑                                  ↓
       └──── 紧凑审计中的未解决项 ← 候选人、原始证据与覆盖对账
                                             ↓ 通过
                                      大学级原子交付
```

Agent 决定学院入口、页面形态、名录分支和有限导航动作。它不得把未核实的分支声明为单页，也不逐人复制完整 HTML 到模型上下文。计划是本次运行的数据：学校、学院、已核实来源、分支入口、允许的点击或翻页选择器、页数与深度上限，以及必要的人工核实证据。不存在按域名选择的代码分支。

导航页与师资来源页是两种角色：科室入口页可以在计划限定的范围内提供下一层链接，但不能因为可导航就自动取得教师来源资格；只有通过页面资格判定的名录、个人页或文档进入人员提取。

## 三个外部模块

| 模块 | 小接口 | 隐藏的复杂度 |
| --- | --- | --- |
| 来源采集 | `capture_sources(plan, browser_context) -> SourceCapture` | 真实 Playwright 浏览器访问、有限分页与子分支遍历、页面快照、访问失败和重试。页面资格判定复用现有 [Page Qualification](page-qualification.md) 设计；Agent 发现入口，资格判定保留确定性审计。 |
| 学院对账 | `reconcile_rosters(captured_pages, plan) -> RosterReconciliation` | DOM/图片/PDF 提取、候选去重、可见卡片与候选人数对账、来源覆盖。它只做来源层对账；`eligible / excluded / unresolved` 的聘任资格由独立领域策略判定。 |
| 大学交付 | `commit_records(records, destination, exporter) -> destination` | 仅接收通过审计的十列记录；大学跨学院汇总、双 Sheet 行互斥与原子替换由同步模块继续负责。 |

`server/harvest_workflow.py` 承载上述通用接口，`server/harvest_eligibility.py` 承载领域资格策略，`browser_batch_tool.py` 只负责校验计划、调用浏览器驱动和组装审计。DOM、OCR 和 PDF 是内容机制适配器，选择器是计划数据。只有同一交互模式在多个站点复现且有跨站测试时，才考虑新增适配器。具体院校的入口、选择器、快照和业务证据留在计划或测试夹具中，不进入通用编排模块。

## 一份可复核的学院审计

完整 HTML、图片和简介留在本地；Agent 只读紧凑审计。审计至少记录：每个计划分支与实际访问的子分支、访问结果、页面资格、可见候选单元数、提取候选数、个人页访问结果、每人的资格证据、排除原因、未解决项和时间成本。数字不一致必须说明原因；无法确定可见人数时不能伪造精确计数。

`delivery_ready` 仅在来源和目标学院匹配、计划分支遍历完整、页面人数差异已解释、候选资格已决、个人页失败已处理且双 Sheet 对已接纳人员守恒时为真。守恒证明分表正确，不能代替网站覆盖证明。来源证据遵循 [ADR 0004](../adr/0004-clinical-faculty-evidence-boundary.md)：大学合格师资名录或医院当前个人页明确大学任职可证明资格；医生头衔本身不能证明。

## 用异构夹具检验设计

- 错误使用 `<header>` 包正文、标准分页、AJAX 分页和两层入口都用独立夹具覆盖；核心代码不读取任何样本域名。
- 可见单元与候选数量不一致时，审计须阻止交付并保留未解释位置；不把页面上的人数自动视为合格教师。
- 导航页只能产出有界子分支或待核实项，不能被当作教师名录直接结束。
- HTTP 400 等访问失败保留浏览器响应证据与重试上下文；只有证据支持时才归因于站点防护。医院名录资格测试属于领域策略验收，不是采集器分支。

## 迁移

保留当前 CLI 和大学同步接口；`harvest_workflow` 的接口先稳定，再分别扩展内容机制和领域证据策略。医院快照继续作为异构领域验收夹具，同时必须有非医院的对照夹具；任何新增站点规则都要先证明是跨站交互模式。旧脚本调度入口继续停用。
