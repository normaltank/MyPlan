## 保护边界与维护

仓库公开仍允许查看、fork 和提交 PR。外部 PR 本身不修改本仓库的分支；合并仍受所有者权限及主分支规则约束。

GitHub 按凭据对应的账号判断权限。所有者授权的开发工具使用所有者凭据时，也以所有者身份操作；这些规则不能分辨同一凭据由本人还是另一程序使用。本地 Markdown 是 agent 行为约定，不是操作系统文件权限隔离，不能阻止同一 Windows 账号下的其他程序写文件。当前未改动本地文件访问权限。

主分支保护可由所有者通过仓库设置维护；更改前需有所有者明确授权。检查权限时同时核对协作者、待接受邀请、全部 ruleset 的 enforcement/bypass、主分支实际应用规则及检查名称。新开发分支可正常推送，但旧 PR 若落后于主分支，需更新后重新等待对应提交的 CI。

当前工作流的 `contents: read` 权限已保留。此保护变更未修改采集代码、运行提示词、生产任务或服务进程，也不证明学院问题已修复。
