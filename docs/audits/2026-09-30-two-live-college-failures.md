# 两张前端工单失败排障（2026-09-30）

本记录针对正式工单 `94c37a15de674b2c956b1469c802678a` 与 `db9a7d3401c34f5b8ef20464360ef5f6`。官网页面、教师数据、PDF 与截图均只保存在本机忽略目录 `server/outputs/debug-recent-20260930/`；本文仅记录技术结论与计数边界。

## 湖南理工学院法学院

原单耗时约 617 秒，三次结构侦察共 147 次模型请求，三次采集均只保留 8 条记录且未通过交付审计。

主名录实际三页为 9、9、2 张链接卡片。姓名附带“博士”“教授”等标签；学历未在姓名槽分离，职称也到分组评分之后才去除，使长标签低分甚至把菜单选为最佳分组。现姓名评分与最终保存使用相同的姓名槽规范化，学历不充当职称，原卡片及完整正文保持原样。本机保存页面重放已恢复 20 条、无卡片差额；真实浏览器重采约 57 秒，仍为 20 条，零新增模型调用。

另一个已发现的官方来源是 PDF.js 嵌入的导师介绍。原普通卡片计划把外层 DIV 当作一张教师卡片；`media_references` 又未识别 `viewer.html?file=...pdf`。现从浏览器 DOM 实际资源参数解析 PDF 路径，不猜测 URL；没有 HTML 人员记录的嵌入 PDF 分支明确转为 `embedded_pdf_roster_requires_review`，不再通过修改卡片选择器反复调用模型，保持交付阻断。

本地原 PDF 有 19 页，其中 16 页有个人文字记录，其余为封面或方向分隔。用修复后的主名录姓名与 PDF 行/span 文字对齐，13 个标签相同，标签并集为 23；其中一页 PDF 标题与正文姓名相互矛盾，正文姓名已在主名录，不能把三个差额标签直接说成三个新增教师。初步使用未规范化标签的 26 人估计作废。另两页标题正文一致，但是否属于本批采集范围仍须核准。学院简介称专任教师 37 人，未见更新日期，只构成范围差额线索，不能作为强制计数阈值。

正式工单保留失败终态与原始费用记录，新诊断审计附在 `attempt-4`，更新为清楚的待核验原因。没有插入教师记录，也没有发布大学 Excel。前端应呈现“来源范围待核验”及原始网页/PDF 链接；这不是已完成的 PDF 名录自动解析或人工批准入口。

## 湖南文理学院美术与设计学院

原单填写“湖南工商大学／国际商学”，URL 实际属于湖南文理学院美术与设计学院。用户确认按链接目标处理，正式库已更正学校学院，在元数据中保留原填写值与确认记录；原单未入库教师数据。

原侦察共 121 次模型请求，约 900 秒超时，未进入确定性采集。顶部初始化的 slick 轮播 Next 被全页探针当成名录分页，单页提交反复遭拒。模型曾删除轮播 DOM 来获得单页证明，原证据校验未能识别这一修改。

修复需同时覆盖侦察 JS 与确定性 BeautifulSoup 分页探针：只有存在完整初始化轮播树，且已核实名录节点不在该轮播里，才把其箭头视为独立幻灯片控件。只有类名、未知控件、实际翻页、教师卡片位于轮播内仍要求验证。`browser_evaluate` 只允许只读侦察，检测到 DOM 修改或探针替换后清除旧证据，重新导航官方页前禁止核验/提交。

26 张可见教师卡片与隐藏图片预加载链接必须区分。机构设置页还含各系教师名单，不能把整页段落数当人数，也不能把这份名单整页按行政页面排除。恢复采集须保留这些来源并逐项对账；独立个人页列表不能证明无个人主页者不存在。
