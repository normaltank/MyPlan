# 前端当前任务与接单状态审计（2026-09-28）

## 问题与处理

旧网页在没有当前请求时，自动读取浏览器中保存的批次 ID，或退回全局最新批次。因此历史上绍兴文理学院 11 个待复核学院一直出现在右侧，仿佛是新请求。两次历史 11 学院批次在数据库中均已结束，交付仍因身份与人数审计而阻断。

现在右侧默认显示“待提交”；只自动恢复该浏览器尚在排队、运行或交付审计中的请求。历史批次只能从“历史工单”主动打开，“新建采集”可清空右侧旧结果，异步响应不会把旧批次重新绘入新视图。待复核卡片改为黄色警示，交付下载仍受服务端门禁保护。历史记录不删除、不重排。

网页现在从 `/api/worker/status` 的数据库心跳显示后台实际在线状态，并用 `/api/history` 展示只读工单摘要。文案与服务器实际流程一致：worker 常驻认领，dsh 与 DeepSeek 仅核实官网结构，浏览器采集与确定性提取随后执行。单院和批量请求均须提供有效的学院官网入口；批量任一行无效时整批拒绝入队。

- 实际浏览器访问本地 Web：默认不展示历史 11 院；明确打开历史后显示 11 条及待复核黄色提示；返回新建后旧结果清空；浏览器无页面异常。证据为 `scratch/web-current-request/result.json` 和同目录截图。
