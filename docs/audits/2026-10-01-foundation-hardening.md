# 底层调用链专项审查与完善

基点 `fe73ddd`。用户授权按实际调用链进一步审阅、脑暴和修复，明确不处理原失败学院，将另选学院验收。用户随后批准职称优先级。本轮只用合成 HTML、本机浏览器路由回放、临时文件与隔离数据库，不访问高校官网，不调用 DeepSeek。

## 入口和设计

[脚本清单](2026-10-01-script-inventory.md)覆盖 69 个底层／启动脚本，65 个 Python 文件做 AST 解析和静态调用者清点。清点不是逐行正确性证明；动态调用、Harness 配置和 CLI 另按实际入口检查。

沿提单、队列、侦察、捕获、恢复、字段提取、覆盖与身份审计、学院导出、大学交付审阅。对交付完整性比较三种方案：

| 方案 | 作用 | 本轮取舍 |
| --- | --- | --- |
| 共享导出校验，保留既有公开入口 | 所有学院／大学 Excel 都无法绕过可表示性检查 | 采用；提前在采集与收据检查相同问题 |
| 采集证据封装为统一 Artifact／Decision | 一次判断字段来源、正文、覆盖和记录摘要 | 暂不引入新数据框架；现有来源与身份审计继续独立执行 |
| 同一验证入口按收据、文件、发布阶段接受不同参数 | 支持导出前检查及工作簿回读 | 只复用实际需要的纯检查／归一化，不引入规则插件或抽象 adapter |

`delivery_fields` 集中十列和字段别名；`excel_export` 检查可表示性并原子写入。两个模块隐藏导出副本与原观察的差异，调用者沿用已有公开接口。数据库收据、人工身份证据及原 HTML 不因导出归一化而改写。

| 调用阶段 | 复现与根因 | 修复 |

| 旧巡检器 | 固定 8000，访问需认证 HTTP 而未登录；无法看到待办 | 本机只读 SQLite 总数，遵循任务库环境变量，不初始化库、不读教师字段、不调用 HTTP；显示统一端口，BAT 使用固定环境 |
| 完整分支恢复 | 缺 evidence 或错误 pages metadata 触发 KeyError，完整 HTML 摘要不足以证明终页 | 验证引用格式、连续序号、终页类型、页面计数及首 HTML 摘要；坏缓存转 cache miss，新浏览失败仍正常报告 |
| 职称 | 正文旧职称覆盖具体名录，晚于 400／500 字的明确字段漏读，共享页按词表长度取值 | 用户批准明确个人职称字段 > 具体名录职称 > 正文首个职称；遍历完整本人范围，single／cluster／shared／fallback／segment／OCR 共用选择规则；明确字段冲突复核，简介不变 |
| 英文职称 | Assistant Professor 被译成讲师；有中文词时忽略更早的英文词 | 改为助理教授，中英文按原文位置统一比较 |
| 联系邮箱 | mailto 目标与显示地址冲突时忽略目标；公共邮箱过滤、无主页卡片纯文本化及候选合并会丢掉冲突 | 在真实 DOM 中保留链接边自身的冲突状态，普通、cluster、共享、降级、无主页卡片和补充名单均以 mailto_address_conflict 阻断；重命名、任职核准、去重及同名合并保留证据，不送结构补缺 |
| 来源提示 | 缺来源快照时仍呈现无问题 | 增加 source_page_unavailable；仍为提示检查，不冒充严格覆盖证明 |
| Excel | 32,768 字简介实际写出 32,767 字，函数仍返回成功 | 共享门禁阻断过长单元格及不可表示 XML 字符，完整原文留 JSON／HTML；既有不可见 XML 控制字符处理保持兼容，不新增正文截断 |
| 导出失败 | 写新表失败时旧路径已被覆盖；空表样式阶段吞掉保存错误可导致 partial ZIP 被误报成功 | 同目录临时文件写完后原子替换，保存错误一律传播，失败保留原交付并清理临时文件；空表和非空表均受保护 |
| 队列收据 | A 大学租约可提交 B 大学记录，直接同步绕过文件路径校验 | 完成前核对全部显式学校／学院别名及单元格门禁，失败不写 records、不结束租约 |

## 验证

定向回归均先确认失败，再实现并转绿。覆盖公开 `harvest_candidates`、`run_plan`、`complete_task → publish_delivery → 实际 Excel` 与导出文件行为；来源提示采用纯公开检查接口。部分 OCR 组合测试保留内部 enrichment seam，用于独立检查原文拼接及字段冲突。

第一轮全量：939 passed、1 failed、1 skipped，389.41 秒。唯一失败是旧正文职称覆盖名录的断言；按已批准新规则更新为具体名录职称，并增加原正文“副教授”仍完整保留的断言，真实 Chromium 定向回归通过。独立整合审阅随后发现并修复英文旧收据的发布漏路径，继续最终验证。

额外独立审阅证实空表保存吞异常、邮箱冲突被 sibling 过滤解除两项组合问题。均先用失败回归重现再修复。原 `ProfileDetail` 数据类字段未增加，缓存的冻结全字段哈希仍通过；`FacultyProfile` 增加状态以让降级／单页路径携带链接冲突，十列交付格式保持相同。目录卡片补充职称原文顺序及物理字段读取回归，不新增“现任／曾任”关键词规则。

第二轮全量 **967 passed、1 skipped**，394.06 秒。随后 Spec 审阅发现无主页卡片的 href 证据漏传；`FacultyCandidate` 新增默认空的 `mailto_conflicts` 确定性元数据，真实卡片 DOM 读取时填入，不写进 card_context 或十列字段。定向回归进一步证实名字确认、医院任职核准、重复卡片和补充名单同名合并会丢掉此元数据，均修复并先红后绿。多人纯名单按卡片记录冲突，不擅自归给某一位教师。

正式隔离核验：618 个 wrappers 缓存／standalone 证据文件的大小、哈希和修改时间相同；正式 tasks 全行与 records 全行摘要相同，仍 89 completed、32 failed。运行中 worker 会更新心跳，不能宣称整个 tasks.db 文件哈希不变。

保存节点：上述 967 项全量在最后的候选元数据修复之前执行；最新候选修复另跑定向组合，结果见下方。不把两次验证混称为最新代码全量通过。本轮尚未重启 Web／worker，运行服务仍是上轮部署版本；提交和推送不等于服务已加载新代码。恢复新学院验收前，应先完成最新全量与空闲时重启。

最新定向组合 **169 passed**，39.97 秒，覆盖候选冲突传递、名录提取、个人／共享联系邮箱、名称确认、补充名单、医院资格、公开浏览器批量流程及职称优先级。Ruff 与 Git 差异检查通过；保存前再次核验正式任务／记录与 618 个受保护文件均未变化。本轮相关代码和 Markdown 保存到 main 并同步 GitHub；不包含其它任务新建的 `Claude outputs/` 文件。

## Standards

独立整合审阅检查 AGENTS／CONTEXT 的字段、浏览器、原文、缓存与交付约束；空表保存与详情邮箱冲突修复后未发现阻断。最后追加的候选元数据传递由主控复核及定向测试核验，未冒称已完成新一轮独立审阅。样式和代码长度不是硬性修复理由。

## Spec

独立整合审阅发现英文别名收据与大学导出不一致，已增加实际发布回归并修复；随后发现无主页卡片邮箱链接冲突，已补齐真实 DOM 证据及候选传递。最后追加修复后，复核子智能体因宿主用量额度耗尽退出，未给出最终独立结论；主控继续完成保存与已有回归，不能把该退出写成审阅通过。

## 保留范围和限制

L1 wrapper 缓存仍保留既有 fail-closed 实现，未因目前闲置而激活或删除；Opus demo/test 脚本是离线合成算法检查，不作为工单入口。生产队列的旧简化收据仍允许省略字段，已提供的范围必须一致；正式浏览器文件收据继续强制标准十列，不因兼容而放松覆盖或身份门禁。

普通邮箱人工裁决入口、PDF 名录分段及范围批准、大学跨学院身份复核界面仍是能力待办；这些不是本轮合成回归可以宣称解决的问题。Playwright 升级和包结构迁移保持暂缓。本轮不证明任意官网适配率，不宣称全国采集准确无遗漏。
