# 宁夏理工学院机械工程学院侦察成本复核

工单 `51ffad482ce3460eb41ccaac631197a3` 于 2026-09-29 08:36（本机时间）由服务器 worker 接单。运行持续约 17 分钟；因用量持续升高，在第二轮侦察尚未完成时人工停止，并将工单标为需排错后重试。没有进入确定性批量采集或生成交付表。

## 可核实用量

第一轮完成后的 `recon-attempts.json`：70 次模型请求，1,542,847 Token，其中 1,417,600 为缓存输入；发现阶段 51 次、936,638 Token，首个导师名录分支 19 次、606,209 Token。该轮因为 `profile_content_selector_missing` 未通过计划门禁。

停止后，从本机 DeepSeek Harness 压缩会话事件逐条汇总第二轮已发生请求：7 个分支共 107 次、1,602,282 Token。两轮合计 **177 次、3,145,129 Token**：非缓存输入 101,624、缓存输入 2,839,424、输出 204,081。第二轮未正常结束，因此这部分用量不在当时尚未刷新完毕的 `recon-attempts.json` 内。网页使用量显示的 149 次、200 多万 Token 是更早的实时截面。

## 原因与边界

- 发现阶段实际访问了 20 个不同 URL，逐一核实师资、导师及系所等名录来源；长对话中的反复工具回传使缓存输入占总 Token 的约九成。
- 第一轮在导师名录的个人简介范围证据上失败，worker 进入下一轮。现有代码会复用该轮的发现结果，但仍需重新核实失败分支并继续检查其他分支。
- 先前同校另一失败工单也发生过 193 次请求、约 275 万 Token。故不能把本次成本归结为 OCR；本单停止时仍在侦察，尚未进入 OCR 或批量采集。

## 处理

最初为立即止损，worker 曾默认在累计 80 次请求或 100 万 Token 时熔断。随后发现固定阈值可能误伤正常复杂学院，已改为管理员可选、默认关闭；启用时 SDK 事件回调逐次计数，触顶后终止会话并保存已知用量，不交付不完整结果。

## 追加根因复核与修订

会话事件显示：第一轮发现阶段调用模型 51 次，返回 11 个分支，其中既有导师入口，也有它指向的名录正文；首个分支的 `browser_verify` 只匹配到 1 张卡片，其链接是另一张多人图片名录。浏览器探针把任意卡片链接命名为 `profileSamples`，计划门禁因而把该链接按个人主页要求正文选择器；模型实际访问了该名录正文，却未调用个人正文验证工具。它最终提交普通名录计划，于是命中 `profile_content_selector_missing`。首个分支的 19 次调用消耗 606,209 Token，输出 Token 84,222 中的大部分发生在此分支；不能仅以“长对话缓存输入”解释全部用量。

随后改动了发现提示词，明确区分真正名录、菜单页与个人详情；分支提示词允许已存在的 `navigation` 计划形态，并要求真实浏览器核实子名录。门禁增加子名录选择器证据检查。结构失败后保留已核实分支，仅重做失败分支；反馈缩小到对应阶段。连续两轮同一问题且无新增已核实分支时停止重复补缺。考虑到固定 80 次/100 万 Token 可能误伤正常复杂学院，费用熔断改为管理员可选，默认关闭。仍保留原有任务时限与最多两轮结构补缺；目前没有付费复跑，不能声称已验证该站点最终能成功交付。

发现阶段的真实浏览器记录还显示，多数页面只有 31～57 个导航链接，旧工具每次只返回 24 个，因此出现了 13 次额外的 `browser_navigation` 请求。导航专用读取上限现为 64，8 KB 总返回上限及 `nextOffset` 未读范围继续生效；真实 Chromium 的 57 链接本地回放一次完整返回。相关 108 项测试通过。这说明能减少此类导航往返，但尚无新的 DeepSeek 实测 Token 数字。
