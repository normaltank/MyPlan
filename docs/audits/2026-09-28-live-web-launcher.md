# 前台提交后无进度：启动入口排障（2026-09-28）

用户从“`双击启动局域网服务.bat`”打开网页后提交内蒙古大学马克思主义学院工单。数据库证明工单被 `server-worker` 认领，独立 DeepSeek Harness 及真实浏览器侦察正在运行；网页的 `/api/task/<id>` 和 `/api/batch/<id>` 却返回 500，使页面无法显示进度。

根因是旧批处理在 `server/` 工作目录用全局 Python 运行 `start_server.py`，入口将 Web 应用按顶层 `app` 导入。任务状态查询再导入 `server.university_delivery` 时，项目根目录不在模块搜索路径，抛出 `ModuleNotFoundError: No module named 'server'`。这可在 `server/` 目录中用同一入口的 TestClient 稳定复现。旧入口还会按端口强制结束任意进程，曾覆盖正在运行的网页服务。

入口现在统一加载 `server.app`，批处理改用项目固定环境并从项目根目录启动；端口被占用时提示关闭旧网页服务，不再强制杀进程。运行中而进度尚为零的任务显示“后台已接单，正在核实官网结构”和“侦察中”。仅切换网页进程，没有重启或重排正在执行的 worker 工单。

隔离回归 `tests/test_web_launcher.py` 与相关前端/worker 测试 18 passed。修复后实际 HTTP 的单任务与批次状态均返回 200；真实浏览器恢复当前批次并显示“自动采集中”，没有发出采集 POST。用户工单在检查时仍为运行中，侦察计划曾有一次契约拒绝并自动进入下一轮，不能把“已接单”当作“已交付”。

排障过程中，一个启动入口回归测试误将“测试大学”工单写入正式数据库并被 worker 认领。发现后已停止该测试 Harness 会话，确认测试任务失败且没有记录，随后只删除该测试工单，审计留在 `scratch/incident-2026-09-28/`。该误测确实启动过 DeepSeek 侦察，不能声称本轮无模型调用。真实用户工单未改动。
