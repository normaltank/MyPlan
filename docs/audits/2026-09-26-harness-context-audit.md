# DeepSeek Harness 指令与 Token 审计

审计日期：2026-09-26。包含 2026-09-24 的四个历史服务器侦察会话与本日同站真实对照；仅统计指令来源、工具行为和 Token 元数据，不复制教师资料或凭证。

## 结论

在实际加载的指令中未发现恶意指令。可确认的问题是职责混杂、无关历史材料进入上下文，以及 Markdown 工作流与服务器实现不一致。不能把每次失败都归因于模型忽略 Markdown。

1. `AGENTS.md` 确实自动注入，四个样本都首先调用了 `faculty-browser-harvest`。不是文件完全未加载。
2. `server/agent_recon.py` 原始提示词只要求侦察和计划 JSON，而采集 skill 描述完整履约。原始提示词也没有宪章要求的 `/browser` 首行。
3. 每个样本加载了 43 项技能目录，模型可见目录约 10,185 字符。`AGENT_HANDOVER.md` 没有出现在该轮文件读取记录中，其体积不能直接解释这轮消耗。
4. 马克思主义学院侦察读取了其他学院计划、其他大学审计，以及 `scratch/hunnu/BRIEF.md`。该手册将学校固定为湖南师范大学，并规定该批次输出目录；它不适用于山东中医药大学。读取事实成立，但没有证明它单独导致了最终错误。
5. 服务器原实现逐单等待，没有 Harness 原生 `subagent` 工具调用。每学院是一个独立根会话，不是模型派发的原生子会话。
6. 原 worker 把 `unresolved` 直接落为失败，与 skill 的补缺流程不一致；本次已加入最多两轮返回侦察的补缺循环。

最后一个样本调用 83 次工具。工具返回序列化文本约 232,776 字符，其中工程 `grep`、`read`、`glob` 合计约 108,254 字符（46.5%）；浏览器快照约 51,947 字符。这是字符占比，不是经过实测的 Token 节省比例。

复核方式：解压对应 `session.v3.jsonl.zstd`，统计 `user/message.source`、`tool/call.name`、`tool/result` 长度；检查 `storages/session_projcache/sessions/<session_id>.json` 的 `tokenUsage`。不需要重新请求官网或调用模型。

## 已实施

- 宪章、领域说明、采集 skill 和当前交接说明移除 2～4 学院分批限制；全部待采集学院立即一对一派发，宿主拒绝时明确报告。
- worker 对全部可认领学院并行启动独立 Harness 会话，不设应用并发上限。它仍不是 Harness 原生子会话树，不应把 asyncio 任务称为原生 `subagent` 工具调用。
- 工单中间文件按 `tasks/<task_id>/` 隔离；同一大学的交付文件在同一个 worker 内按序写入。
- 侦察提示词补齐 `/browser`，明确仅侦察的职责，排除无关旧作业手册与历史工程搜索，并要求紧凑 DOM 信息及选择器实际验证。
- 6 个学院在任意一个结束前全部开始的测试先失败后通过；`--once` 仍只处理一单。
- `server/recon_instructions.md` 是侦察指令的直接来源。专用运行配置关闭通用技能目录、自动工程指令注入、文件搜索与终端工具，保留真实 Playwright。
- 采集审计失败后，在原工单租约内最多补缺两次；反馈只含经过校验的结构计划、错误状态、URL、选择器与数量，不复制教师字段。
- 每轮审计保存模型步数、工具调用与缓存/未缓存输入、输出 Token。SDK 初始化和请求超时分别设定，异常不再统一误报为外层侦察超时。
- 已停止空闲旧 worker，启用锁定依赖环境下的新 worker；启动日志确认全量并行派发，无项目级并发上限。

## 省 Token 优先级

1. **专用侦察 profile**：关闭通用技能目录、工程工具及无关自动指令注入；项目阶段指令由运行代码读取。
2. **工具层结构预算**：项目 MCP 单次文本最多 8000 UTF-8 字节，范围明确回传 `nextOffset`；无法内联时明确返回未完成，完整证据留本地。教师简介不受预算影响。Harness spill 配置已启用，主要作为图片及兼容工具回退；不是主要文本预算执行器。
3. **阶段独立上下文**：先发现全部名录 URL，再为每个分支创建新侦察会话，只开放当前阶段所需工具。控制器合并已验证计划，不让全部页面历史反复进入每次模型请求。
4. **可执行工作流门禁**：URL 须来自成功的浏览器结果，选择器须实际匹配，分页须实际打开下一页或观察到同 URL 内容变化；不完整计划最多修复两次，失败不得交付。
5. **整项指标**：累计全部阶段及补缺调用的未缓存输入、缓存输入、输出；全量并发本身不代表 Token 减少。

## 验收边界

固定环境 `.runtime/worker-venv`、Python 3.12、`requirements.lock` 下完整回归：**165 passed、1 skipped、225 warnings，17.49 秒**（2026-09-26）。警告来自 BeautifulSoup/lxml 的弃用参数。历史 145 项结果已被后续验证替代。

### 同站实际对照

同一湖南中医药大学信息科学与工程学院官方入口。累计 Token 包含所有模型步骤的重复输入；缓存输入不能与未缓存输入按同一单价估算费用。原始元数据见 `scratch/harness-token-comparison.json`。

| 配置 | 步数 | 首请求输入 | 未缓存输入 | 缓存输入 | 输出 | 累计输入加输出 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 基线 | 17 | 16,610 | 16,649 | 391,680 | 4,608 | 412,937 |
| 专用运行配置 | 21 | 7,995 | 18,459 | 313,344 | 7,682 | 339,485 |
| 仅精简指令的早期实验 | 21 | 7,935 | 24,173 | 547,456 | 7,775 | 579,404 |
| 分阶段、结构工具与证据门禁 | 29 | 2,777 | 18,029 | 213,632 | 8,144 | 239,805 |
| 同配置独立复测 | 26 | 2,777 | 16,419 | 168,448 | 5,528 | 190,395 |

最后两次完整侦察累计 Token 比基线分别减少 **41.9% 与 53.9%**，平均减少 **47.9%**；首请求输入减少 **83.3%**。两次真实采集均得到 **89 人、5 人有邮箱、84 人无邮箱、零未解决项**，`姓名` 与 `主页` 组成的 89 个身份集合与基线完全一致。因此，同站样本已实现整项任务 Token 减少；尚不能保证所有学院都有相同降幅，也不能把 Token 降幅当作费用降幅。

早期策略并不稳定：仅精简提示词累计消耗增加；过小的工具预算造成更多往返；降低推理强度的试验仅采到 73 人；没有分页门禁的首次分阶段试验仅采到 88 人且存在未解决项。以上方案均未采用，不能计入成功的省 Token 样本。

### 补缺、完整性与证据复核

- 真实故障注入：把已核实计划的首分支卡片选择器改为不存在的选择器。首次实际浏览器审计失败，worker 在原租约内将安全结构反馈返回真实 Harness，修复后实际采集恢复 89 人（5 + 84），身份集合与基线一致。实际补缺侦察累计 277,203 Token；故障注入的首轮明确标记为 fixture，未调用模型。原始记录：`scratch/harness-repair-smoke.json`。
- 独立代码复核发现并修复：补缺不能删除 `known_urls` 或 `previous_plan` 中已核实的分支；同 URL AJAX 下一页不能被当作无分页；HTTP/HTTPS 或尾斜杠等重定向只根据成功的真实浏览器导航证据建立 URL 对应；含邮箱或用户信息的非法 URL 在进入补缺反馈前被拒绝。
- 原先一段验证脚本错误使用英文 `name/profile_url`，对中文列返回了空身份。该比较无效。当前使用强制索引 `姓名/主页`，两个最终成功样本以及补缺样本重新核对了实际 89 人集合；旧实验中该错误比较标记已撤销。不得声称完整记录所有字段逐字一致。
- 收尾改动后的真实浏览器重放仍为 89 人（5 + 84）、零未解决项、89 个身份一致，记录在 `scratch/harness-final-replay.json`。重放没有新增模型请求，收尾的分支/URL 卫生校验及提示词补充尚未重新测量 Token，表中的降幅对应收尾前的两次分阶段实测。
- 本地常驻 worker 改用 `.runtime/worker-venv` 固定环境及锁定依赖；旧临时环境可能随启动器退出被清理，导致后续 MCP 浏览器无法启动。启动日志确认全部学院一对一并发，无项目级并发上限。它仍是学院独立 Harness 根会话，不是 Harness 原生 subagent 工具会话树。
- 未重跑历史 17 个失败工单；没有验证 Linux 常驻部署、所有 WAF 站点或多 worker 的大学交付互斥。上述单学院验证不代表任意学院零遗漏。
