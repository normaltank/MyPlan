# MyPlan 项目说明：目标、技术路线与当前阶段

接手本项目的人或 agent 先读本文件。这里只写稳定的方向和已定的决定，细节以链接文档为准。阶段变化时只改第 7 节，并写日期。

## 1. 项目是什么

前台同事按学院提交工单：大学、学院、学院链接，以及可选的师资列表链接。后台按以下流程处理：

1. 在真实浏览器里找到该学院的官网师资名录。
2. 采集专任教师的姓名、职称、邮箱、个人主页和完整简介。
3. 经审计后，按大学交付双 Sheet Excel，在本机网页下载。

- **采集单位**：学院。每个学院一张工单，独立侦察、采集、审计。
- **交付单位**：大学。同一大学的目标学院全部通过审计后，生成 `server/outputs/<大学名称>.xlsx`。
- **表格**：两张表，`教师列表`（有邮箱）和 `无邮箱教师列表`，10 列相同、行互斥。

## 2. 目标与成功标准

**原则：错一条比漏一条更糟。** 拿不准的姓名、邮箱、身份、来源范围进入人工复核，不猜，也不静默放进任何一张表。

按优先级排序：

1. **准确**：每个字段都来自官网原文，并能追溯到本地页面快照；简介保留原文全文。
2. **覆盖**：已核实的名录分支全部采到，翻页到达终点，可见卡片数等于提取人数。官网上是否还有未发现的名录入口，需要另外的导航证据。
3. **成本**：模型 Token 只花在结构侦察上。降低消耗不得降低采集效果和准确性。
4. **速度**：在以上三项都满足之后再追求。

**量化标准（待用户确认）：**

| 指标 | 目标 | 现状 |
| --- | --- | --- |
| 已交付字段准确率（抽检口径） | 待定 | 有抽检工具，尚无统一基线 |
| 人工复核占比（按学院或按人） | 待定 | 未统计 |
| 每千位教师的侦察成本 | 待定 | 早期“0.7 元/千人”未经端到端验证，不可引用 |
| 单学院耗时上限 | worker 默认 45 分钟判定卡死 | 已有分阶段耗时报告 |

## 3. 范围：采谁、不采谁

**采：** 目标大学的专任在职教师。临床学院按[ADR 0004](adr/0004-clinical-faculty-evidence-boundary.md)，只收有大学聘任证据的人。

**不采：**

- 行政人员、辅导员、实验教辅、离退休人员、外聘客座。
- 没有大学聘任证据的医院医生。
- 研究生院、国际教育学院、荣誉学院这类零编制机构，按 0 人交付（见 [CONTEXT.md](../CONTEXT.md)）。

**同一个人：** 补充名单上的名字，如果学院里恰好只有一位有个人主页的同名教师，就算同一人（“唯一同名即合并”）。同名的个人主页有两个及以上时，送人工复核。

## 4. 技术路线

### 4.1 四层分工

| 层 | 谁来做 | 产出 | 失败时 |
| --- | --- | --- | --- |
| 侦察 | DeepSeek Harness 在真实浏览器里核实官网结构（全项目唯一的模型调用） | 采集计划：只含 URL 和 CSS 选择器，不含任何教师数据 | 停止，或在同一租约内补缺侦察，最多 2 轮 |
| 采集 | Playwright 按计划翻页、访问个人页；确定性算法提取字段 | 十列记录和本地页面快照 | 访问失败重试；结构问题交回侦察 |
| 审计 | 覆盖账本，加上身份、邮箱归属、资格、来源范围检查 | 未解决项清单 | 任何未解决项都阻断交付；需要人判断的进入网页复核 |
| 交付 | 队列入库，大学版本发布 | 不可变的大学版本 Excel 和清单 | 同一大学的学院未齐或有冲突时不发布 |

### 4.2 为什么这样分

- **模型只判断结构。** 网站结构千差万别，判断名录在哪、翻页按钮是哪个、页面属于什么类型，需要智能。但模型产出的数据会有幻觉，所以模型只管“去哪里、看哪块、点什么”，数据一律由确定性代码从页面原文提取。计划卫生检查是这条边界的执行判据：计划里出现中文即视为数据外泄。
- **站点差异放进计划数据，不写进代码。** 每个网站不同的地方表达为选择器，不为某个网站写专用脚本或关键词黑名单（[ADR 0005](adr/0005-plan-driven-browser-harvest.md)、[ADR 0003](adr/0003-cs-principled-deep-module-extraction.md)）。职称词表和姓氏表只用来判断“这段文字是不是姓名或职称”，不用来删改页面内容。
- **默认不放行。** 双 Sheet 守恒只证明分表正确，不证明没有漏人。是否漏人由覆盖账本证明：计划的分支是否全部采到、翻页是否到达终点、卡片数是否等于人数。
- **证据留在本地。** 原始页面、PDF、数据库和产出只放在本机被 Git 忽略的目录里，不进 Git，不上传。

### 4.3 生产路径与代码位置

现在只有一条生产路径：本机常驻 worker。AGENTS.md §3 里的 IDE 子智能体派发规则，用于人工辅助采集。

```
server/app.py（网页、提单）→ server/agent_queue.py（tasks.db，带租约）
→ server/agent_worker.py（每个学院一个协程）
→ server/agent_recon.py（侦察）→ server/browser_batch_tool.run_plan（采集、审计、学院表）
→ server/browser_batch_sync.py → agent_queue.complete_task（守恒检查）→ server/university_delivery.py（大学版本）
```

逐层的模块和函数见[内核调用链审查](audits/2026-09-30-core-chain-review.md)第一节，页面类型见 [README](../README.md)，恢复、缓存与完成条件见[可验证运行流程](architecture/verifiable-harvest-runtime.md)。

## 6. 验证口径

汇报时写明证据属于哪一层，不跨层引用：

1. **单元测试和合成页面测试**：只说明代码行为符合预期。测试使用隔离数据库，不访问网络。
2. **本地快照回放**：对已保存的页面成立，不代表官网当前状态，也不代表没有快照的历史数据。
3. **有限实网验证**：需要用户同意，只覆盖访问到的学院。
4. **交付**：工单状态为 completed、审计没有未解决项、大学版本已生成并可下载。

## 8. 工作约定

- **环境：** Windows 本机。
  - 开发用 `.runtime\dev-venv\Scripts\python.exe`，生产用 `.runtime\worker-venv\Scripts\python.exe`。
  - 改了代码，双击 `重启本地服务.bat` 才生效。
  - `.runtime/restart_after_roster_fix.ps1` 是旧草稿，不能运行。
- **测试：** 全量 `python -m pytest -q`（含 `browser` 标记）、`ruff check .`、`git diff --check`。`tests/conftest.py` 已把队列库和侦察证据隔离到临时目录。
- **正式库只读：**
  - 查询用 `sqlite3.connect('file:server/tasks.db?mode=ro&immutable=1', uri=True)`。
  - 只输出计数，不输出姓名或邮箱。
  - 改动之前先用 SQLite 的 backup API 备份。
- **改动方式：** 先写一个会失败的回归测试，再修。每个修复都要有证据、根因和测试；同时更新 CHANGELOG 和[审阅待办](review-backlog.md)。
- **Cowork 环境的坑：**
  - `device_bash` 是 Linux 虚拟机，跑不了 Windows 的 exe，而且不能删文件。只读的 git 命令加 `--no-optional-locks`；不要在虚拟机里对检出的分支执行 commit 或 checkout。
  - 桌面控制里终端只能点击，不能输入，需要在 Windows 上执行的命令请用户运行。
  - 云端和虚拟机都没有 GitHub 凭据，推送由用户在 Windows 上完成。
  - 多个 agent 可能同时在本仓库工作：开工前先看 `git status`，不要覆盖或顺带提交别人未提交的改动。
