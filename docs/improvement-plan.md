# MyPlan 当前改进计划

更新：2026-10-10。状态：工作指导；下列审查、修复与验收尚待逐项执行，不能据此宣称已完成。

需求依据见 [CONSTITUTION.md](../CONSTITUTION.md)，当前实现和验证状态见 [AGENT_HANDOVER.md](../AGENT_HANDOVER.md)。用户最新明确要求优先；旧审计、方案和交接记录只能作为线索，须用当前代码与证据核实。本文件第一节记录已确认方向，后续是执行方法，不代表用户已批准具体成功率、样本数量、费用或部署时间。

## 一、已确认的目标与顺序

先更新开发与运行指令，再并行审查代码质量和采集有效性。当前重点是提高采集准确度、完整性与可运行性；服务器部署、通知渠道及批量输入清理后续处理。

输入为大学、学院、学院链接和可选师资链接。系统应发现并核验师资入口，输出四列入口映射表；已有师资链接是优先入口，仍须检查其他分支。采集官网明确列为师资的全部人员，包括兼职、外聘，输出姓名、职称、邮箱、大学、学院、个人主页与完整简介，官网缺失字段如实留空。

允许先交付已核实部分并标明缺失范围；身份或邮箱归属不清的记录单独待核。同校确认同一人后合并学院归属，不能仅凭同名合并。人工确认“无师资学院”单独计入处理结果；抓不到数据仍是失败或待核。

## 二、工作线 A：全链路代码质量与契约审查

从生产入口追踪实际调用、数据结构和状态迁移，覆盖下列边界：

| 范围 | 必须核对的问题 |
| --- | --- |
| 输入、侦察、计划、执行 | 三列/四列输入是否一致；运行提示词、校验器和提取器是否采用同一师资范围；分支与分页信息是否完整传递 |
| 队列、错误、重试、人工复核 | 失败能否正确分类；重试是否重复工作或丢失证据；人工决定如何影响恢复；任务状态是否与实际产物一致 |
| 提取、审计、大学汇总、导出 | 字段是否归本人；资格与身份规则是否一致；部分结果、待核记录、完整交付是否混淆；聚合是否漏人或误合并 |

同时检查重复实现、职责交叉、隐式依赖、死分支、异常吞没、复杂度和累积补丁，主动发现尚未表现为工单报错的问题。每项结论附文件/函数、调用方、具体冲突或可复现情形；按影响和证据决定局部修改或模块重构，不能只因文件长、代码旧就整体重写。

输出审查清单，区分已确认缺陷、需验证的风险、可维护性问题。修复按独立问题组织，明确行为变化和相关回归；已有未合并改动先核对，避免重复修复或相互覆盖。

## 三、工作线 B：采集有效性与泛化验证

新随机任务用于发现未知问题，原失败复现用于定位原因，两者持续结合：

| 样本组 | 用途 | 使用规则 |
| --- | --- | --- |
| 历史回归集 | 保持原有成功能力，验证已知错误不再出现 | 同时保留成功与失败案例，以及修复前证据 |
| 随机探索集 | 从真实业务输入范围发现新失败 | 先冻结抽样再采集，可据结果调试 |
| 未见验证集 | 评估冻结版本对新学院的表现 | 未参与调试，运行前冻结版本、样本和判定方法 |

从用户实际待处理母表随机抽取新学院，记录母表版本/摘要、抽样范围、稳定排序、随机种子、排除规则和选中列表。样本规模按人工核验能力确定，不用一个固定小样本数充当质量门槛。用户可直接通过现有系统发起批次，无需先重建输入工具。

常见业务分布由随机样本反映；图片、PDF、复杂分页等难类型可另补样本，单独统计。按大学和模板族标记相关性：同站多个学院不能算多次独立跨站验证；同模板新站与新模板的结果分别说明。留出分组在查看结果前固定，披露与调试集的大学或模板重叠。

抽中但不可访问、输入有误、人工确认无师资、尚未运行的项目全部保留并说明状态，不能悄悄换成容易成功的学院。失败样本参与修复后转入回归集；已经查看并据此调试的验证集失去独立性，下轮使用新批次。

## 四、基准证据与指标

基准由用户或同事核验，覆盖成功和失败结果。逐学院确认官方分支、分页、目标人员及身份关系，再逐人逐字段核对来源与完整简介；不能只对导出表计数。探索和留出样本都应检查表面成功的结果，生产阶段再采用异常复核加正常结果抽查。

每轮同时报告：

- **原始通过率**：程序声明自动通过数 / 全部已提交的抽中学院数，并列尚未运行数。此项只描述流程表现。
- **核验后有效范围表现**：在人工确认输入指向真实目标且应有师资的学院中，完整正确完成数 / 该有效范围学院数。已确认有效者的运行时访问失败仍计入分母。逐项披露排除理由，资格未知、暂不可访问和人工无师资分别列出。
- **人员与字段质量**：正确输出人数 / 全部输出人数，另列漏采人员、错填与漏填字段、官网未提供字段、待核记录，以及分支/分页缺口。仅在完整名单真值已确认时计算召回率；真值未知须标未知，不能声称全采齐。
- **使用代价**：耗时、模型调用/费用证据和人工复核量。把大量问题转为待核，不能算自动采集能力提高。

人数宣传与名录不一致须保留差异证据；已核实人员可部分交付，差额不直接等于漏采人数。`delivery_ready`、两表人数守恒或测试通过都不能单独证明准确完整。

## 五、执行与交接

每轮持久化输入、抽样记录、代码提交、实际运行版本、配置、模型及提示词版本、采集时间、计划、页面/附件原件、审计、输出和人工真值。缓存、模板复用及重试条件须固定并记录；需要比较冷启动和复用时分开报告，保留修复前后证据。

以现有 [回放入口](../server/case_replay.py) 和 [验收测试](../tests/test_harvest_acceptance.py) 为审查起点，核实资源完整性、缓存行为和比较粒度是否满足上述要求；能力不足处列缺口，不假定已经支持。保存页回放验证固定材料上的行为，实网验证当前访问、导航与资源取得，两类证据分开报告。

执行顺序：更新指导文档 → A 线审查与 B 线抽样准备并行 → 保存首轮证据 → 修复共性问题并跑相关回归 → 冻结代码后运行未见批次 → 更新交接与下一轮清单。

文档修改、代码提交、测试通过、用户机器已加载、真实任务验收分别记录。更新仓库不等于更新用户正在运行的服务；本计划不触发实际付费采集、部署或通知。
