# Claude 限时额度任务：解决实际采集阻塞

用户授权在 Claude Code 网页版、GitHub 仓库 `normaltank/MyPlan` 开发。每项单独分支与 PR，以包含本文件的最新 main 为基线；不自动合并或部署。

先完整读根目录 `CONSTITUTION.md`、`AGENTS.md`、`CLAUDE.md`，再按任务读取相关代码与 `docs/review-backlog.md`。宪法、生产架构和字段标准保持不变。项目已有通用采集、PDF、OCR、身份复核、断点恢复、租约与双 Sheet 导出，优先复用。

这是实现任务，交付可运行代码和行为回归；仅写分析、整理文件、改格式或新增类型标签不算完成。不能以放宽门禁、丢弃未知人员、截断简介、AI 转写字段或改测试预期获取成功。

开发只使用隔离数据库与输出目录。不得读取或修改本机生产库、重排历史工单、调用付费生产侦察。云端无法访问官网时，使用当前仓库样本和独立生成的测试附件，明确报告实网未验证，不虚构采集结果。

## 任务 A：让多人 PDF 名录进入确定性采集链

### 实际问题

网页正文只有 PDF.js／嵌入 PDF 或名单下载链接时，普通 DOM 卡片不含附件里的教师。目前会出现 `embedded_pdf_roster_requires_review`。已能读取 PDF 原件、文字层和扫描页，缺口是多人分段、字段归属及整合采集证据，不能把整个 PDF 容器当一名教师。

真实公开问题入口：`https://zhengzhi.hytc.edu.cn/info/1132/19852.htm`。这是研究生导师简介补充来源，不得据该 PDF 宣称全学院采齐。原件若可访问，只用于核验与本地样本，不提交教师个人数据到仓库；测试使用合成或脱敏材料。

### 先读与复用

- `server/image_biography.py`：`media_references`、`fetch_browser_asset`、`scan_media`。
- `server/harvest_workflow.py`：名录对账与嵌入 PDF 阻断。
- `server/browser_batch_tool.py`、`server/segmented_roster.py`：字段归属、分段、OCR、证据和采集整合。
- `server/recon_contract.py`、`server/agent_recon.py`：只在必要时增加结构计划字段，保持模型字段隔离与本轮浏览器证明。
- `tests/test_image_biography.py`、`tests/test_image_pdfjs.py`、`tests/test_embedded_pdf_roster.py`。

### 实现范围与验收

1. 取得浏览器实际观察到的 PDF 原件，保存来源、内容哈希、页码和读取方式；覆盖嵌入与实际下载链接，不能臆造 URL 或拿错误 HTML 当 PDF。
2. 有效文字层直接读取；扫描页使用现有本地 OCR。逐页保留完整文字和可用位置证据，避免把页码／水印当有效全文。
3. 用确定性结构／版面证据划分多人记录，归属姓名、职称、邮箱与完整简介。至少验证一页多人、跨页续接和图文混合；无法唯一分段、姓名冲突、低置信度或公共邮箱须留未解决证据。
4. 接入现有候选人、覆盖对账和交付门禁；网页与 PDF 重复观察不能增加虚假人数。保留来源资格审核，附件读得出不等于来源已批准。
5. 普通 DOM 名录、个人 PDF 简历与图文混排回归保持行为；输出仍为标准十列及双 Sheet。
6. 若“任意 PDF”不能可靠自动拆分，应交付有明确支持条件的通用适配器、实际失败证据和安全复核路径，不增加每学校脚本或用模型兜底提取。

主要代码归属：PDF 适配模块、采集整合、必要的结构契约与对应测试。不要同时重做 Web 复核页面、登录权限或队列调度。

## 任务 B：普通 HTML 邮箱歧义的人工复核与恢复

### 实际问题

现有普通 HTML 采集能发现多个邮箱或归属冲突并阻断交付，但 `docs/review-backlog.md` 明确记录：完整人工裁决入口仍缺。图片 OCR 邮箱复核、姓名复核与部分身份复核已有实现，不能让员工永远停在“待处理”。

### 先读与复用

- `server/field_checks.py`、`server/detail_mecc.py`、`server/faculty_extractor.py`、`server/browser_batch_tool.py`：查明实际产生的 HTML 邮箱冲突及证据结构，不凭错误码猜业务含义。
- `server/app.py`、`server/templates/image_review.html`（以实际文件为准）、`server/image_bio_review.py`、`server/task_image_review.py`：现有复核、权限与恢复模式。
- `server/harvest_state.py`、`server/agent_queue.py`、`server/access_control.py`：证据缓存、任务归属、租约及单工单重试。
- `tests/test_authenticated_image_review.py` 及现有邮箱冲突／复核测试。

### 实现范围与验收

1. 用隔离样本复现真实普通 HTML 邮箱冲突，保留本人正文范围、候选地址及原始页面／哈希。先写失败行为回归，再实现修复。
2. Web 对有权限员工展示必要的原始上下文，允许选择有证据的个人邮箱；只有已有证据证明无个人邮箱时才可确认空值。不提供任意填写、猜测或把公共邮箱强行归人的入口。
3. 人工裁决绑定工单、教师／来源观察、候选集合与证据版本。来源变了或候选地址变了，旧裁决不得自动放行；其它教师和其它任务不能复用裁决。
4. 保存全部必要裁决后，复用现有单工单恢复流程，确定性重新审计。不得为了重试重跑全部已完成采集／付费侦察，不绕过其它未解决项与大学交付门禁。
5. 验证无权限访问、跨工单裁决、过期证据、未决冲突、合法裁决、重复保存及失败恢复；保留图片 OCR 邮箱审核的原有行为。

主要代码归属：普通 HTML 邮箱裁决模块、现有 Web 复核／恢复整合及相关测试。不要新增 PDF 解析器，不修改任务 A 的适配模块；需要新增邮件审计数据时，在现有格式中增加必要证据，避免重构整个提取内核。

- 保持宪法和已定架构不变；若必须改变核心契约以外的原则，停止该部分并报告具体阻碍。
- 完成当前任务后报告 PR 和结果，等新指令；不要顺手升级依赖、改包结构、清理全仓或启动其它重写。
