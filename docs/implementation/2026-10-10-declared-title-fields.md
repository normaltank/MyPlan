# 明确职称字段保留复合原值

资源学院本轮7个个人页在一个明确字段内列出并列或限定职称。旧读取器把每个识别词扁平化，选择器又将多个词当作多个矛盾字段，产生假冲突。保存页证明每处只有一个本人字段，不能让人工随意选一个词而丢失另一部分。

`titles.TitleField` 保留字段原值、识别词、物理文本行范围及边界疑义；`detail_mecc.explicit_title_fields` 每个明确字段产生一个对象。纯已知职称和纯英文职称沿用规范值，复合／聘任／等级限定保留原值。`select_title` 比较不同字段的值，而非同字段内词数；重复等价值不重复，不同字段或混入其他标签仍阻断。

个人页明示、名录具体职称、正文首个未标注提及的既有优先关系保持。single、cluster、名录、fallback、shared、分段和图片正文统一消费此模型；图文两个真实不同字段仍冲突。简介和原始HTML不修改，不增加学院、姓名或URL特例，不新增模型调用。

旧 `explicit_title_candidates` 保留为识别词兼容视图，生产选择不再使用扁平接口。未知职称默认值、无主页字段和其它交付差距未在本增量宣称解决。

新增合成反例在旧版5项均失败；相关59项通过，涵盖四种复合值、真实矛盾、优先级、完整简介及共享／图文／分段路径。固定7份实际浏览器保存页按原SHA核对后独立回放，原字段值全部保留、7项假冲突消除、正文逐字不变。结果仅以URL、SHA和结构计数保存在开发工作区 `.planning/compound-field-replay.json`。回放不替代本轮实网或学院完整性验收。

当前是开发实现；独立审查、全量CI及生产加载待核。Word目录、超长全文交付和空／失效个人页另行处理，不以职称修复掩盖。

独立审查发现仅根据行末运算符续写仍会丢字段：逗号后换行、分隔符写在下一行均可被截短并误报交付成功。现由 `declared_dom_title_fields` 读取完整物理段落或表格值单元；字段内换行保留，兄弟段落不合并。`ProfileDetail`、`FacultyProfile` 和名录候选携带确定性字段对象，后续选择不重新从简介猜边界。分段用本人片段原始 HTML；图片增补将本人 HTML 字段与原生／OCR 文本字段分别比较，不把共享页其它人的字段归入本人。

纯文本没有 DOM 边界，遇到可能续写的相邻职称表达式保留疑义，不能成功交付截短前缀。悬空括号／运算符、另一个字段标签仍阻断，括号内聘任冒号仍保留。这些反例由实际 `harvest_candidates` 和媒体增补路径核验；正文读取器不因字段解析改变简介。

后续审查的缺陷也已形成回归：独立标签段落只与紧邻值段落组成字段，不能跨过正文或另一个人的标题；容器直接文本单独读取，不把子容器里的人员再次扁平合并。多人共用名录卡片保留人员和共同字段，但共同字段没有本人归属证据时仍待核，本人详情的明示字段可按原优先级覆盖。第二个字段标签不因前置句号、感叹号或其它标点而被吞掉。媒体增补只重读已有正文范围证据集合中的单人 HTML，不将范围失败时保留的原整页侧栏当作本人字段。

本地最新定向96项通过，包含完整采集、图文增补、旧聚类输出指纹和逐页索引次数。聚类指纹比较保留全部旧字段，新字段对象作为内部证据另验；不是更新旧指纹来掩盖数据变化。全量测试与独立复核最终结果仍以冻结提交记录及 CI 为准。

最后补充标准定义列表 `dt/dd` 的标签／值配对；字段值内再出现人员标题时保留边界疑义。共享页媒体追加消费采集时已读取的本人字段证据，不能因为 URL 共用而把该字段降回缺少 DOM 边界的字符串。字段证据通过可选的内部输出参数传递，不进入十列记录、计划 Schema 或对外审计 JSON；分段内容仍优先读取其本人的原始片段。
