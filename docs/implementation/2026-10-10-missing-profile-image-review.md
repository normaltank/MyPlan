# 失效个人页图片的人工用途复核

## 领域与处理边界

信息工程学院三个个人页的正文正常，正文图片在重复浏览器访问中返回404。缺失原件无法靠尺寸或模型判断是否承载简介/邮箱。此前仅为访问失败，没有可操作复核项；用户指出应该进入后台人工复核，本改动补这一缺口。

这属于采集失败/人工复核类型，不是新的网站页面形态。扩充现有 `review_registry` 的 `media_kind` 登记，复用原决策文件、授权接口、恢复拷贝和复核页面；不建立学院专用解析器，不新增生产模型入口。

`missing_media_review` 独立管理缺失原件的证据。身份绑定请求个人页URL、浏览器最终个人页URL、图片URL、已核实正文选择器/起点、选中正文SHA和HTTP状态；它不是原图SHA。重定向后的实际资源基址由本轮浏览器证据独立传入媒体审计，不依赖失效图片列表；快照按请求记录定位。原件不存在时界面显示来源、失效状态及完整可见正文，用户只能确认已知仅为教师照片或保留未知/文字阻断。不能通过这类决策转写图片中的教师字段。

## 代码行为

1. 两次真实浏览器访问均观察到该正文图片404/410，且正文范围稳定、可见、有完整文字，才创建待复核证据。一次404、先403后404、正文无文字、隐藏范围、替代图源保持阻断。
2. 正文范围证明与缺失图片数据的可用性分开。撤除原有正文图按尺寸自动忽略的路径，小图和无尺寸图也不能据此认定用途。媒体审计仍尝试取得原件：恢复后的图片正常走原件/OCR审计；任意异常、403或暂时故障不能变成照片豁免。
3. 未决定或未知用途阻断完整交付。已保存的人类photo决定只适用于同一证据身份；正文/图源/状态变化即失效。完整可见简介和失败证据保留。
4. Web保存复用现有账号/任务授权/CSRF与media-kind接口。用户此前明确确认的三张教师照片可由维护操作记录聊天确认引用，不能冒充Web账号；正常后续流程通过后台复核页。
