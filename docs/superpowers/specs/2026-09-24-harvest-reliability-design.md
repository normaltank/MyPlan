# 学院采集可靠性加固设计

## 目标与不变量

前台按学院提交任务，服务器 worker 持租约完成浏览器侦察、真实浏览器采集、确定性字段提取、覆盖审计，最后按大学交付双 Sheet。模型只能产出已核实的地址及 CSS 控件；姓名、职称、邮箱和简介仍由确定性代码取得。既有历史人工计划与服务器模型计划应区别校验，不能让较宽的人工证据字段进入模型产出。

## 方案选择

方案 A 是全面重写浏览器采集器及提取器，改变面广且难以证明没有回归。方案 B 是保留深模块接口，针对计划、覆盖、交付三个接缝增加可执行门禁，并用真实名录反例改进姓名召回。采用 B；每项改动有独立失败用例和回归结果。

## 模块与数据流

1. `agent_recon` 对服务器模型计划实施严格字段契约，学校和学院必须与任务一致。只接收来源种类、分支地址、实际核实的卡片与导航 CSS 选择器及整数上限；拒绝任何人工核实候选、任职引文、任意附加字段。URL 是地址字段，需按 URL 解析；不能仅凭字符串前缀免除字段卫生检查。
2. `browser_batch_tool` 在名录页验证卡片选择器。`single_page` 仅是待验证声明：若页面存在可疑分页入口，则阻断交付并保留证据，不把第一页当成完整名录。无法确定页面覆盖时进入 `unresolved`。既有显式 `next_selector` 继续由浏览器点击和名录签名变化验证。
3. `faculty_extractor` 对同构名录组中的生僻姓使用组结构作为额外证据，不再单凭封闭姓氏表静默丢弃；组外的普通词仍不能获得相同豁免。页面卡片与候选人数必须继续对账。
4. `agent_worker` 仅在同步和大学表实际完成后报告交付成功；失败保持有租约围栏的落库语义。
5. 依赖版本与部署路径以可复现配置为准；文档区分历史结果、当前回归与尚待真实网站验证的事项。

## 错误处理与验证

模糊的分页、卡片数量不符、计划额外字段或同步失败都不得生成成功结论。先写可重现失败的测试，再做最小实现；运行目标测试与全量离线套件。真实站点覆盖和 Linux 常驻运行需单独实测，离线测试不替代这两项证据。
