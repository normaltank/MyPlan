# 员工工单隔离与每日统计设计

## 目标

员工使用平台内账号密码登录。新工单绑定提交人；员工只能查看自己的历史、详情、下载和统计；管理员可以查看全部并创建账号。旧工单没有可证明的提交人，只给管理员查看。学院采集及大学交付的业务边界不变。

## 数据与权限

- 在现有 SQLite 中增加用户、会话表和 `tasks.owner_user_id`。批量提交在同一事务里为每个学院写入相同的提交人。
- 会话使用随机令牌，数据库只保存其哈希。浏览器持有 HttpOnly、SameSite Cookie；变更请求校验 CSRF。密码使用带独立盐的慢哈希。
- 工单、批次、历史、大学版本下载均在后端按提交人授权。旧记录的 owner 为空，普通员工不可见。界面隐藏不是权限边界。
- 后台队列认领、续租和同步接口只能从本机调用；网页响应不得暴露 `lease_token`。管理员可查看全部业务工单，但后台租约只在后台路径传递。
- 本地 HTTP 只允许回环地址登录；给局域网同事使用时必须经 HTTPS 入口。

## 页面

未登录显示登录表单。登录后显示当前员工、退出按钮、本人工单和本人的每日数据。管理员另有创建账号及全员统计入口。浏览器当前工单指针按账号隔离，切换账号不恢复上一人的工单。

## 统计定义

以 Asia/Taipei 自然日计算：提交学院数按 `created_at`，完成学院数和通过审计的教师记录数按 `finished_at`。教师记录数是本日完成工单的行数，复采会再次计数；不称作去重后的教师人数。当前后端把审计未通过和技术失败都标记为 `failed`，所以本阶段只展示失败数；待后续接入独立的人工复核工单状态后，再单列待复核数。

## 验证

用两个员工与一个管理员的独立会话测试：提交、历史、直接猜工单 URL、批次详情、下载、旧工单、统计与切换账号。另核对后台租约不出现在员工响应中，未登录请求被拒绝，worker 仍能续租和同步。
