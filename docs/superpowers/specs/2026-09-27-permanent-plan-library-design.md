# 永久采集方案库

## 目标与授权

用户要求将七天结构缓存改为专门数据库永久保存，已有持续实施授权。执行数据库迁移和验证，不另设批准等待。

## 选择

采用 SQLite 版本库，与现有任务数据库技术保持一致。单纯延长 JSON 有效期仍不能保留同学院历史版本；无期限 JSON 可以工作但缺少版本和验证查询；SQLite 支持原子并发写入、永久历史及验证记录，适合当前本地部署。

## 契约

- 路径为 `server/outputs/plan-cache/plans.sqlite3`；结构版本没有默认到期时间，不自动删除历史。
- 保存完整结构计划、入口、导航 URL/指纹、契约摘要、创建时间及内容摘要；不保存教师数据字段或浏览器全文。
- 旧 JSON 自动导入，保持原时间、摘要与契约，原文件保留；损坏或含教师字段的文件拒绝导入。重复导入幂等。
- 相同结构、导航证据与契约去重，原 `saved_at` 保持；成功采集后再次保存更新 `last_seen_at`，候选按此时间和版本序号选取，历史结构重新启用仍能成为最新候选。浏览器验证时间单独记录。契约变化、摘要错误或非法结构不复用，不能回退到旧版本绕过审核。
- 每个新工单复用前继续真实浏览器检查全部导航证据、卡片和实际分页，记录紧凑验证时间/结果/原因；数据库读取不是验证通过证明。
- 原有显式 `max_age_seconds` 保留为可选调用策略，不影响永久保存；生产默认无时间上限。
- 不改变页面快照的 24 小时恢复期限，不修改采集正文、覆盖和身份门禁。

## 验收

跨年仍可读、重开实例仍保留多版本、旧文件导入不丢失/不重复、并发写入安全；非法摘要、结构、数据字段和契约变化仍被拒绝。浏览器导航和分页变化继续使复用失败。失败回退到 Harness，验证记录不进入模型上下文。
