# 随机学院验证与适配修复实施计划

**Goal:** 用预先冻结的新院校真实样本暴露适配缺陷，建立可重复的失败证据并修复。

**Architecture:** 官方抽样框与浏览器证据独立保存；学院子智能体提交核实计划，原采集内核运行于隔离目录。结果汇总不删除失败样本，通用修复由真实快照回归保护。

**Tech Stack:** Python 3.12、Playwright、现有采集/审计模块、SQLite、pytest。

- [x] 获取官方候选名单，冻结随机学校样本和排除规则。
- [x] 每校从真实官方院系导航随机选择学院，保存候选与种子；按宿主实际能力派发并记录拒绝。
- [x] 执行新学院真实浏览器验证，保存快照、计划、独立对账证据及失败原因。
- [x] 选择可重现的通用缺陷，先写失败回归再修内核；保留失败及修复前后比较。
- [x] 汇总全部抽中学校，区分结构验证、采集、交付与 Harness 自主侦察的证据范围。
- [x] 独立复核、相关和全量测试，更新交接及空闲服务。

固定解释器 `.runtime/worker-venv/Scripts/python.exe`。测试数据库为 `scratch/verification/tasks.db`；真实验证资产为 `scratch/random-college-validation/`，不同步生产。

完成记录见 [六校随机验证审计](../../audits/2026-09-27-random-college-validation.md)。365 通过 / 1 跳过；1 校独立通过，5 校明确阻断。本计划完成代表测试、修复和部署闭环完成，不代表所有外部访问与身份问题已解决。
