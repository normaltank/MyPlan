# 图片简历识别与本地 OCR 实施计划

> 本计划依据 [已核实官网样本](../../research/2026-09-28-image-only-faculty-examples.md) 和用户对处理决定的授权执行。采集计划仍只含 URL 与 CSS；教师字段不进入模型输出。

**目标：** 浏览器采集遇到图片承载的个人简介时保留原件和本地 OCR 证据；无法核清的内容阻止 Excel 交付。

**架构：** 在已采集的 HTML 正文容器中识别实际引用的图片和 PDF，用同一浏览器上下文读取这些官方资源。新建独立的图片正文审计模块，输出紧凑状态与本地证据路径；批量流程将未解决项接入现有交付门禁。保留 DOM 原文提取的既有路径。

**技术：** Python、Playwright、BeautifulSoup、PyMuPDF、RapidOCR、pytest。

官网样本验证范围：湖南科技大学前 3 张原图完成本地 OCR；其 2021 年 45 张图片页也已用真实浏览器做只读全页试跑。试跑识别出 45 个候选，保留 43 份图片原件与 OCR 证据；2 张当时因网络失败未取到，1 张 OCR 置信度未过审，覆盖核对未通过，故未生成正式 Excel。此后对那 2 张原件的单独重试成功，但尚未重跑整页核对，不能宣称该页已完整采集。西北民族大学 PDF 在新建 Chromium 会话遇到验证码，已验证 HTTP 200 HTML 会被识别为资源失败。当前实现不能自动破解验证码，也不能自动把一份多人 PDF 准确切分归属；这两类情况留在未解决项。

回归结果：图片正文、正文范围、浏览器批量和验收测试 105 项通过；侦察、缓存、结构证据与 worker 交付测试 63 项通过。扫描 PDF 即使带有页码等极少文字层，只要主体是覆盖整页的图像，仍走本地 OCR。只读试跑保存在 `scratch/image-bio-acceptance`，正式大学输出目录未写入本次试跑结果。常规 HTML 正文中顺带链接的 PDF 在正文已充分呈现时不会被当成图片简历处理；若官网把额外履历放在这类链接里，目前仍需人工确认该链接是否应纳入正文范围。

后续诊断：45 图页的一次新输出目录重跑在完成 8 张后中止，已完成证据保存在 `scratch/image-bio-acceptance-rerun`，不能把它算作整页验收。对同一张本地 JPG 的计时为 OCR 引擎初始化约 0.23 秒、首次识别约 49 秒、同引擎再次识别约 22 秒；低置信图片的放大、灰度增强和锐化均未使唯一低于 0.8 的行越过门槛。因此当前优先事项是提供针对未解决行的人工复核与断点续跑，而非直接降低置信阈值或为整页反复调用模型。
